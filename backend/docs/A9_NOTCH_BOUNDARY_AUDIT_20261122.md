# A9凹口判据与实际边界核查

本轮未修改生产代码或验收规则，没有调用新DeepSeek请求。新增只读回放工具`evaluations/audit_heart_notch.py`，重放上轮失败运行`live-corpus-2ee7db_f`中的模型计划，使用项目保留的原文及最终真实补参，核对实际修正后边界。此次诊断不重写原成绩。

## 重要更正

上轮报告的归一化高度0.99是“实际采样边界到既有验收窗口的最近见证点”，并非中央凹口高度。仅凭该数值推断“最终计划凹口过浅”不够准确。此次沿包围框中心竖线与实际多边形相交，取上边界，再与左右两侧采样峰值比较。

## 用户要求与经验判据

用户要求平滑、左右对称的爱心及宽高中心，没有指定凹口深度。现有`center_notch`窗口要求中央附近边界的归一化高度在0.5至0.9之间。对4米高的轮廓，0.9意味着相关点至少低于全图最高点约0.4米。这是当前经验形态阈值，不是从用户原文解析出的凹口尺寸。

因此有两个不同问题：三份中央仍隆起的计划有实际形态问题；两份浅凹口计划则触及经验阈值与用户未指定深度之间的边界。浅凹口存在并不证明整个图形就是合格爱心，也不能据此自动升为正式候选；仍需双瓣、轮廓拓扑、平滑、对称、尺度及来源验收。

本轮不降低阈值、不改分数，也不把诊断结果算作后端生成能力提升。下一步应将“实际中央凹陷及双瓣关系”的通用边界测量与“未明确指定的最小凹口深度”分开设计和验证；如需调整经验规则，单独版本化，并保留旧规则成绩。对于真实生成错误，继续向已有修复链提供边界关系，不能用增加专用生成器处理。
