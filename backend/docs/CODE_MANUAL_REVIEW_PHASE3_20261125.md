## 3. 四项新增运行时证据

所有样例来自 `.local-dev/code-capability-audit-20261125/phase3_probes.py`，结果保存在 `phase3-probes.json`。使用现有隔离环境、实际归一化函数和实际确定性执行器；没有 HTTP 正式交付测试，也没有用人工假验收替代来源验收。

### 3.1 补齐起点会改变明确的二次曲线和样条

位置：`cad_construction_interpreter.normalize_composite_path_connections_once`，尤其第 2455–2465 行。

代码只检查下一段存在三个控制点且起点不衔接，没有在这一分支检查 `kind == bezier`，也没有使用前面算出的 `fixed_source` 保护用户控制点。原文明确要求保留控制点时仍会补点。

复现：第一段控制点 `(0,0),(1,1),(2,0)`，第二段 `(3,0),(4,1),(5,0)`。执行器原本拒绝不连续复合路径；归一化器把 `(2,0)` 插入第二段后，执行器通过。

- Bézier 从三个变为四个控制点，二次曲线变成三次曲线。
- `degree=2` 样条也被同一个 `complete_composite_bezier_start` 分支插入控制点，形状和端点改变。
- 原始传入字典没有被就地修改；问题在返回的修复计划，不是浅拷贝污染。

样例的固定端点本来与“单条连续复合路径”的表示冲突。正确边界应是报告冲突、选择合适的独立表示或请求修正规划，不能靠改写明确控制点消除错误。**这里证明归一化层越界，不证明后续完整来源验收已经错误交付。**

### 3.2 上下半圆方向没有绑定到具体对象

位置：同一函数第 2467–2489 行。

原文同时要求两个独立圆弧：中心 `(0,0)` 的上半圆和中心 `(5,0)` 的下半圆，半径均为 1 米。输入计划的两条圆弧正确，执行器通过。

归一化器在整段原文找到“上半圆”，对每个步骤都采用 `upper`，把第二条圆弧从 `clockwise=true` 改为 `false`。两个弧的起止角均为 0→180 度，第二条因此从下半圆变成上半圆。修改后的计划同样可被执行器执行。

这是来源修复的对象作用域缺失；单对象方向修复已有实现，不应再开发新的半圆生成器。**最终来源验收是否拦截需要另做完整链路验证。**

### 3.3 局部连接容差没有参与实际判定

位置：`cad_construction.JunctionConstraint`、`AddCompositePathStep.effective_junction_constraints`、`_validate_composite_path_quality`、`_composite_continuity`。

合同允许每个连接单独设置 `tangent_tolerance_deg`，有效约束表也会计算这个值。但 `_composite_continuity` 使用整体 `step.tangent_tolerance_deg` 产生 `continuity_passed`，后面的筛选只取局部连续性级别，没有按局部容差重新判定。

使用同一处实际夹角 2° 的连接，局部意图为 `smooth`、要求为 `G1`：

| 整体容差 | 局部容差 | 按局部合同应得 | 实际执行器 |
|---:|---:|---|---|
| 5° | 1° | 拒绝 | 通过 |
| 1° | 5° | 通过 | 拒绝，`c1_continuity_failed` |

证明的是执行器对现行局部合同的落实错误。样例没有模拟来源授权通过，因此不能扩大为正式交付漏洞。

另有待明确的语义：`c1` 当前主要由切线夹角判定，诊断自己标记为 `G1`，导数虽记录却不比较大小。不能据这个字段名称宣传已完成严格参数 C1 连续性验证；应先明确工程合同再决定调整实现或名称。

### 3.4 原生 Bézier 与复合路径对同一曲线给出不同边界

位置：`cad_construction._bounds` 第 2048–2049 行及 `_execute_step`；对照已有 `drawing_store.geometry_preview_paths`。

控制点 `(0,0),(1,2),(2,0)`，单位米。二次 Bézier 的 `y(t)=4t(1-t)`，最大值为 1 米。这与两种表示的实际预览一致。

| 表示 | 构造测量的宽×高 | 实际曲线/预览宽×高 | “宽2米、高2米”断言 |
|---|---|---|---|
| `add_bezier` → 原生 `spline` | 2×2 米 | 2×1 米 | 错误通过 |
| `add_composite_path` → 采样多段线 | 2×1 米 | 2×1 米 | 正确拒绝 |

根因：`_bounds` 对 `spline` 直接读取控制点范围，把控制多边形边界当成曲线边界。该函数还用于对象边界、布局参照和中心距，影响范围应逐调用点继续核对。存在独立来源验收并不免除构造层提供准确几何事实的责任。

同文件 `_closed_geometry_area` 对闭合样条也使用控制点多边形，属于同类待验证风险；本轮没有单独完成闭合周期样条面积复现，不计为第五项确认错误。

## 4. 查重与整合判断

可以整合的是重复的协议处理和测量语义，不能按名称相似直接删除：

1. **同一曲线的测量基准。** 已有公共几何测量和预览采样工具，构造 `_bounds` 仍保留另一种含义。先明确“真实曲线边界”“保守控制包络”“预览边界”各自用途，再复用正确底层；不能把全部调用直接换成固定密度预览采样。
2. **有限修复的授权与对象绑定。** 来源索引、固定点识别、连接权限都已存在，但部分局部修复没有使用它们。应统一接入已有证据和明确输出引用，不新建一套相同来源系统。
3. **验收结果归并。** 解释器依次调用许多来源测量器，并在多处分配 `coverage=complete`；已有公共归并函数和单次测量缓存。可以整理统一调用/结果协议，但每个覆盖证明仍须保留各自消费原文、实测和拒绝条件。本轮没有证明这些覆盖分支可以互相替代或直接合并删除。
4. **试算复用。** `_trial_plan_without_assertions` 会被引用修复、布局、面积和尺寸处理重复调用；已有证据缓存不能自动证明这些不同计划可共享结果。后续应按完整计划哈希和执行条件检查可复用性，不能只按原文或对象名缓存。

本轮判断仍是：先证明并整理已有能力边界。最紧要的不是增加生成器，而是确保修复保留用户固定参数、关系绑定到正确对象、等价表示得到一致测量。待剩余核心模块读完，再形成包含依赖和迁移顺序的最终整合方案。
