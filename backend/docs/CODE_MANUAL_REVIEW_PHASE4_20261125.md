## 2. 已证实的重复执行分支

`edit_candidate_geometries` 是公共入口，但内部仍有两套执行分支：

- 图元/逻辑对象解析为 `geometry_ids` 后，复制、镜像、偏移和阵列进入 `cad_selected_operations.apply_selected_operation`。
- 按 `instance` 选择则继续进入 `incremental_cad._edit_candidate_geometries` 的各实例分支。

`cad_edit_contract_to_edit` 明确保留这两种目标作用域；服务也会将实例解析结果直接交给公共编辑执行器。不能把实例分支认作仅测试使用的死代码。底层点变换有部分共享，但偏移算法、镜像重合处理、复制与阵列预算、创建实例/图元 ID 仍分别实现。

需要保留的语义差异：操作一个实例、多个实例分别绕各自中心、多个实例绕组合中心、修改明确图元选区，确实有不同的目标与枢轴合同。应让这些合同调用统一几何操作，不是把所有目标一律改成同一类选区。

### 3.1 实例偏移将等距操作变成缩放，公共预检无法识别

原始矩形为 10000×2000 毫米，要求向外偏移 1000 毫米，分别选择同一几何的实例和图元：

| 目标表示 | 新边界 x 范围 | 新边界 y 范围 | 新宽×高 | 预检/变化计划 |
|---|---|---|---|---|
| 实例 | -5000…15000 | -1000…3000 | 20000×4000 mm | 均通过 |
| 图元选区 | -1000…11000 | -1000…3000 | 12000×4000 mm | 均通过 |

原边界 x=0…10000、y=0…2000。等距偏移应使每侧距离均为 1000 毫米；实例分支使左右距离变成 5000 毫米。

原因：实例分支第 2519 行附近按最短边计算统一缩放系数，再整体缩放。选区分支已对闭合多段线调用几何 buffer，支持真正的等距偏移。**不是缺少偏移能力，而是旧分支仍使用另一种算法。**

实例错误结果的 `effect_validation.verified=true`、`preflight.ready=true`，无需风险确认；`edit_plan.verification.verified=true`。这几项证明合同重放和变化范围一致，没有证明等距性质正确。`relation_validation.enforced=false`；现有独立对象关系验收只覆盖符合条件的同心/相等关系。

测试 `test_offset_rectangle_scales` 明确把 2000×1000 矩形内偏移 200 后的宽度设为 1200，而逐侧等距结果应为 1600。该断言固化了缩放行为；本轮未修改此测试。不能只看测试通过就认定偏移语义正确。

### 3.2 对称镜像的实例回退会生成重复 ID，公共门槛正确拦截

同一对称矩形，左右镜像并保留原图，未指定外部镜像轴：

- 图元选区分支拒绝重合结果，要求明确轴位置或副本位移。
- 实例分支先过滤与来源重合的边界，随后回退为把原图平移一个完整宽度。
- 回退重新 `deepcopy(selected)`，未保留前面分配的新 ID 与新实例号。单多段线样例得到几何 ID `[1,1]`、实例号 `[1,1]`，同时 edit 声称 `new_instance=2`。
- 执行器返回非空结果，但预检的稳定 ID、目标范围和来源保护检查拒绝，`ready=false`。

这包含两个问题：未授权的额外平移，以及回退丢失新身份。不能通过删除 ID 保护或放松预检处理。

前轮全量离线测试的 63 个失败中，`TestMirror.test_mirror_fully_symmetric_shape_rejected` 已暴露这一异常；本轮对照进一步解释了重复 ID 的实现原因。它不是本轮新引入的回归，也不能简单归为陈旧测试。其余失败没有因此自动完成归因。

### 3.3 环形阵列把实例序号当成份数

原文：`将第2个图形做环形阵列，共6份，每60度。`

实际规则解析：`instance=2`、`array_mode=polar`、`count=2`、`angle_degrees=60`。执行后包含原实例 2 和副本实例 3，共 2 份，未满足 6 份要求。

原因：环形份数正则从整句第一个数字开始匹配，`个/份` 后缀可选，于是先命中“第2个”中的 2。中文数量表 `_ORDINALS` 还只覆盖到五，其他数字词支持不完整，后者本轮仅作静态边界记录。

错误结果仍通过合同、预检和变化计划；阵列标为高风险，需要确认。这里没有绕过确认，也未证明确认后最终保存。重放按错误合同得到同样结果，不会自动回查原文的 6。

现有解析测试含“第1个图形环形阵列6个”，但只检查 `operation` 与 `array_mode`，没有检查 `count`；执行测试则直接传入正确 count，跳过了原文参数绑定。

### 3.4 续句改写丢掉第二个平移方向

上一轮已持久化实例 1 的平移。新消息：`把它向右移动1米并向上移动2米`。

| 路径 | 得到的位移 |
|---|---|
| 同一消息加图形上下文后直接解析 | dx=1000、dy=2000 mm |
| `resolve_incremental_followup` 改写后再解析 | dx=1000、dy=0 mm |

改写结果只剩 `第1个图形向右移动1米`。主解析已有 `_compound_translation`，重复上一轮和纠正路径也有多轴处理；普通续句显式距离分支却只取第一个匹配。

HTTP 的 `_normalize_cad_followup` 使用这一改写结果，后续链解析不能恢复已被删除的第二个动作。此处验证到实际改写函数和接入代码，没有模拟完整会话 HTTP 交付。现有续句测试覆盖单轴和重复前次操作，没有用本样例证明多轴信息保留。

## 4. 验收层已有能力与实际边界

已有以下分工，不宜再新增一套同名组件：

1. `cad_edit_intent` 记录目标、参数、约束、缺失项和来源元数据。
2. `cad_edit_contract` 验证命令形状、必填参数、ID 和链式范围。
3. `cad_edit_gate` 对执行结果做合同重放、数值有效性、稳定 ID、目标范围和非目标哈希检查；只对已支持的编译对象关系增加独立测量。
4. `cad_edit_plan` 生成并校验变化 ID 清单，有限修复恢复意外改变的非目标，不凭空补造缺失的预期变化。
5. `cad_edit_chain` 逐步执行、逐步预检，任一步失败不返回成功的完整链结果。

这里的合同重放是有价值的一致性证据，但与执行器共用算法，不能独立证明算法本身正确，也不能证明原文参数已正确绑定。变化清单能证明改了谁，不能证明“偏移”等几何性质。部分计划中新增 ID 来自实际结果，需与来源要求和独立性质验收分开描述。
