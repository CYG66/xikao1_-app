## 1. 当前判断

项目已经具备可复用的二维 CAD 构造、编辑、约束适配、来源证据和交付基础。当前主要问题是这些能力在不同入口之间的契约和证据传递不完全一致，不能简单归结为模型不稳定，也不适合继续按失败图形增加专用生成器。

目前不能称为通用自然语言 CAD 模型：核心是外部语言模型规划，加规则解释、二维构造 IR、确定性执行和独立验收；没有证据证明任意自然语言、任意组合约束或通用三维实体建模都能完成。二维投影视图与三维实体建模应分开。

“工具已经实现”“语言入口可以表达”“生产链路可以执行”“来源要求得到独立验收”“正式保存并交付”是五个不同层次。后续能力表必须分别记录，不能以某个执行函数存在就认定完整能力已交付。

## 3. 已复现的问题

### 3.1 位移数值出现于原文，不代表绑定到了正确的方向

位置：`app/cad_edit_interpreter.py` 的 `_distance_values_mm`、`_direction_grounded`、`_ground_interpretation`；以及后续 `cad_edit_gate.validate_declared_edit_effect`。

原文：`将第1个图形向右移动1米，并向上移动2米。`

正确模型参数为 dx=1000、dy=2000 毫米；把它们对调为 dx=2000、dy=1000 毫米后，模型适配器仍返回 `grounding.verified=true`。原因是距离被收集为无序集合，方向仅验证词语与符号，未证明每个数值属于对应子句和轴。

继续使用已有执行器和预检：圆心实际从 (0,0) 变为 (2000,1000)，执行无错误，预检 `ready=true`，声明效果核验 `verified=true`。后面的核验验证了合同执行正确，没有重新证明合同符合原文。

证据：`edit-grounding-differential.json`、`edit-grounding-through-preflight.json`。

**证明范围是模型适配器→现有执行器→预检。尚未证明该错误必然穿过完整 HTTP 路由与正式保存。** 规则解析可能优先处理该原句，因此不能把这个探针直接换算成用户请求失败率。

应复用现有来源事实与编辑合同，建立字段、方向、数值、原文片段之间的绑定；不能只添加另一个“证据字符串属于原文”的检查。

### 3.2 等价单位表达在规则生成入口产生不同结果

在现有 `interpret_construction_request` 中，用下列三个表达描述同一个圆：

- 圆心 (2,2)，半径 1.5 米，坐标单位为米：`ready`。
- 圆心 (200,200)，半径 150 厘米，坐标单位为厘米：`invalid`。
- 圆心 (2000,2000)，半径 1500 毫米，坐标单位为毫米：`invalid`。

后两项实际错误分别包含圆心坐标 200000、2000000 毫米超过限制。规则解析器把点值直接放进 `units=m` 的计划，半径却单独换算，显式坐标单位没有得到相同处理。

位置：`cad_construction_interpreter.parse_rule_construction_plan`、`_parse_clause`、`_point`。验收侧 `cad_source_acceptance.verify_single_round_primitive` 又有自己的坐标单位选择逻辑。已有 `cad_length_units` 和坐标来源契约，应先接通，不再新写一个单位系统。

全套测试中的 `circle_centimeters` 也体现了同类分歧：计划圆心为 (2000,3000) 毫米，来源测量认为应为 (20,30) 毫米。原测试没有明确坐标单位，不能据此直接裁定哪一组坐标符合用户意思；上面的显式单位对照消除了这个歧义。

证据：`additional-probes.json` 的 `explicit_coordinate_units` 和 `circle_centimeters`。这仍是解释器级复现，未进行真实模型 HTTP 调用。

### 3.3 精度预算尚未覆盖所有测量表示

`cad_precision` 已定义构造采样 0.2 毫米、来源验收 0.5 毫米；这项能力已经有了。

但 `drawing_store` 的预览仍用固定 `CURVE_SAMPLES=64`，`cad_geometry_measurements.path_geometry_facts` 又将预览采样用于部分路径关系测量。半径 5000 毫米的半圆分成 32 段，首段弦高中点偏差约 **6.022719 毫米**，大于上述预算。

`cad_path_relation_acceptance.assemble_closed_boundary` 的圆弧分支已有独立有界采样，因此不能笼统说“所有圆弧都没有精度控制”。真正的问题是测量消费者使用的表示不一致。应区分显示精度、独立测量精度和精确变换比较精度；不宜把所有 0.001/0.5 等阈值机械替换为同一个数值。

另外，离线 Bézier 极值测试的 4 个失败已追溯到执行阶段：自由轮廓放大后误差超过 0.2 毫米，执行器保守拒绝，离线测量适配器返回 `execution_or_geometry_not_supported`。并非已证明极值公式计算错误，也不应放宽精度门槛让它通过。需要核对组合曲线采样是否能按最终布局放大倍数重新细分；参数曲线分支已有类似处理，可先检查复用边界。

证据：`additional-probes.json` 的 `arc_preview_precision`、`offline_minimum_trace`。

### 3.4 同步与流式交付对请求上下文的传递不一致

位置：`agent_http_service._agent_chat`、`_agent_chat_stream_events`、`agent_chat_stream`、`resume_agent_run`。

同步适配器会把 route 中的 `execution_context` 放进结果。流式适配器没有同样补齐；流式入口随后用 `result_generated` 检查点替换先前的 `context_prepared` 检查点时，也没有保存 `execution_context` 或 `prepared_context`。

离线故障注入得到：相同的有效冻结上下文通过前置核验，同步结果含上下文，流式结果不含；在真实流式检查点写入之后、最终交付之前注入中断，检查点实际缺失两类上下文。将该隔离运行模拟为超时暂停后，真实恢复函数返回“检查点缺少原始请求上下文，拒绝恢复，请重新发起请求”。

**范围：使用真实同步/流式适配器、检查点写入和恢复门槛，准备上下文及上游成功结果是注入夹具，没有真实模型或真实 CAD 构造。** 这证明的是传递与恢复缺口，不能声称已经完成自然语言 CAD 的完整在线断连实验。有些上游结果自身携带上下文，可能不触发该问题；但流式适配器不能普遍保证它。

证据：`stream_context_probe.py`、`stream-context-probe.json`。应复用已有结果最终处理、上下文和检查点协议进行收敛，保留恢复接口对缺失证据的拒绝。

### 3.5 “中间对象”的重复选择策略已经产生不同结果

已全文复核 `cad_target_resolver`。同一模块的逻辑对象、普通实例、带类型实例有重复的“中间”选择策略，但并不等价：

- 两个圆分别在 x=-2000、2000 毫米，没有唯一中间圆。逻辑对象和带类型实例分支要求澄清；普通实例分支却直接选择实例 1，并给出 1.0 置信度。
- 三个圆按实例 ID 1、2、3 分别位于 x=0、10000、5000 毫米。普通实例和逻辑对象分支正确选择位置居中的第 3 个圆；带类型实例分支按排序后的 ID 选择实例 2，即最右边的圆，也给出 1.0 置信度。

这证明“同样几何、同样中间语义，因为目标表示或类型过滤不同而选出不同对象”。故障在解析器层复现，尚未验证完整 HTTP 编辑保存；不把底层可调用等同于所有路由必然进入这个分支。

证据：`additional-probes.json` 的 `middle_target_representation`。应优先统一现有中间目标的轴定义、空间排序和歧义策略，保留版本/选区等权威引用的优先级，不能直接用其中任一当前分支覆盖其他分支。

## 4. 已确认的契约差异和生产事实

1. **编辑入口可表达范围不同。** 执行合同支持 17 类操作，结构化模型解释仅 12 类；模型目标类型和选择字段也比现有对象图、规则目标解析更窄。这是已有能力的暴露问题，不应新增同名执行器。
2. **生产存在条件性 SketchGraph 恢复。** `agent_service.py` 约 6610 行之后，特定多对象构造失败会调用多候选解释，再将候选逐个送回现有完整来源验收。`cad_construction_evaluation` 中“生产始终单计划、多候选仅离线”的说明已与生产代码不一致。不能依靠旧文档判断调用链路。
3. **重试限制分散在多个层次。** 生成修复、结构化输出修复、多候选恢复、候选生成入口重试、计划步骤恢复不是一个计数器。单个函数有最多两次修复，不等于整轮请求只有两次模型调用。后续应先跟踪现有计数与请求记录，不再并列增加新重试层。
4. **执行计划不是逐条语义验收的替代品。** `agent_plan_runtime.begin` 常创建一个 `execute-request` 步骤与 `request-result-valid` 条件；`complete` 综合结果和现有断言形成状态。`cad_plan_verifier` 也把整体验证结果映射到步骤条件 ID。目前不能据此声称每个尺寸、关系都已经逐项求值。
5. **候选保存本身已有证据门槛。** `persist_candidate_variant` 不再凭几何存在制造通过；底层 `add_variant` 也区分缺失验收、草稿和正式候选。针对缺失证据的旧保存测试，应修正测试构造以真正执行保存逻辑，不能删除生产门槛。

另有待核实点：`construction_acceptance_summary` 在后验结构通过时会消除预检的待复核状态，现有一个测试要求保留所有上游复核状态。代码注释意图是消除“预检无法展开”的临时不确定性，但目前通用布尔值不能完整表达复核原因。这是需要细分原因并追踪真实调用的契约争议，**不能仅凭该单元测试就断言已出现完整生产误交付**。

## 5. 查重结论：哪些能合，哪些不能直接合

### 可以考虑提取的实际重复

AST 函数体跨文件比较（忽略文档字符串，至少 5 行）发现 **7 组生产代码重复**，另有 2 组测试/手工脚本重复。该阈值会漏掉短函数及语义相似实现，不能当作全项目重复率。

| 重复位置 | 建议 | 约束 |
|---|---|---|
| `cad_constraint_solver` 与 `native_constraint_worker` 的 points/size/rotate，另有较短 translate | 可提取纯几何辅助函数 | 保留进程隔离、角度单位、原生后端适配和错误语义 |
| `agent_plan_sqlite_store` 与 `database` 的连接和上下文管理 | 可共享很薄的连接基础函数 | 不合并计划事件存储与业务历史存储 |
| `agent_skills`、`cad_edit_gate`、`drawing_commands`、`geometry_catalog` 的正 ID 转换 | 可统一纯转换函数 | 先确认布尔值、浮点截断与非法值策略；收益较小 |
| `geometry_catalog._number` 与 ROS 处理中的局部 finite | 低优先级 | 数值用途不同，不能只为了少几行而扩大公共依赖 |

### 类似但需要先证明等价

- 多个 bounds/points 实现：已复现同一非法坐标在目标解析中被跳过，在编辑边界计算中抛异常；还有圆弧全圆外包、实际弧段、预览采样外包等语义差别。先定义用途和差异测试，再选择复用，不能直接替换。
- “中间对象”在同一解析器中有三套相似策略，已复现 ID 排序和空间排序不一致、偶数对象歧义处理不一致；这是优先整合项，详见 3.5。
- 矩形测量：公共 `rectangle_frame` 能处理共线细分，关系编辑中的严格原语检查要求四个角点；是否接受等价表示应明确，不能把两者直接视为完全重复。
- 原文维度、坐标、角色解析：多个消费者确实重叠，且已产生单位分歧；应沿现有来源事实契约统一共享数据，保留独立测量。不能把生成和验收合成同一个自证过程。
- 精确名称参考解析在 `cad_object_constraints` 内已经存在，但用于特定两对象约束的固定参考方。它可以成为复用依据，不能直接当成任意移动目标名称都已经支持。

### 不应再次合并或误删

- 几何事实缓存、公共 JSON 指纹、部分结构测量包装已经整合，不应根据旧报告重复实现。
- 生成重试、编辑受保护图元恢复、执行计划恢复属于不同责任。
- 会话项目焦点、版本绑定、对象选择、几何身份属于不同引用层。
- 候选验收、逻辑图一致性、编辑预检、正式保存分别守护不同边界；函数数量多不能直接证明重复。
- 不同哈希协议包含不同字段、规范化和版本含义，不能只因都使用 SHA-256 就互换。

## 7. 暂定优先级：先完成评审，再落实现有能力修复

1. **继续完成未读代码与失败归因。** 补齐大型服务、HTTP 同步/流式/恢复、编辑执行、会话与存储剩余分支，审读工具和评测入口。能力表的未证实项继续保留，不能先按缺失能力开工。
2. **优先修复已证实的目标选择、原文绑定、单位与上下文传递。** 复用已有来源事实、单位转换、目标解析、编辑合同及检查点，先保证中间对象选择、字段归属、同义单位、同步/流式恢复一致。保留独立几何验收与恢复完整性门槛。
3. **收敛测量表示与采样预算。** 优先接入已有测量器，处理最终布局放大、原生曲线与等价分段表示；显示采样不能代替误差有界测量。
4. **整合已有入口和恢复责任。** 对照现有模板、规则、模型、对象引用和保存门槛，明确同一要求如何到达同一验收；先记录整轮调用预算与失败类型，再决定是否调整恢复策略。
5. **建立可信的验证分层。** 合同与纯几何验证、无模型的完整生产链路、同源冻结的真实模型多次重复、未见表达留出测试分别出成绩。原始 70 条可保留回归用途，不能作为泛化能力的唯一证据。

以上是基于已审读证据的暂定修复顺序，尚未开始新功能研发。本轮没有为了消除失败而修改任何生产门槛或测试断言。
