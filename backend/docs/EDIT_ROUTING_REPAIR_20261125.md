## 已证实根因与修复

原E1/E2请求都附带完整句“只生成预览，不执行小车”。`parse_incremental_edit`原先看到“小车”就退出，`fresh_creation`又因“生成”返回True。直接对三个原句运行原函数，得到三次`(True, None)`。

两函数现在复用既有`partition_preview_intent`，只分离该完整交付意图句；额外真实“执行小车”仍令编辑解析退出，不扩大运动授权。

HTTP原先仅在携带drawing_selection时稳定覆盖新建分类。现在请求已绑定有效project/variant、原句可由现有编辑解析器识别、且不是新建时，也进入modify；同时设置现有`incremental_cad_edit`分派键与`resolved_edit`。不伪造对象选择，不将项目ID等同于已选定具体对象，原版本归属检查保持。

第一轮修复仅改modify分类，未绑定执行器，仍退回模型对话；第二轮补齐已有分派契约。两轮均在各自冻结版本运行，中途不改源码或评分，记录未覆盖。
