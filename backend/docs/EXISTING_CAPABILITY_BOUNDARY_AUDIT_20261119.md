## 结论和证据边界

本轮只新增审计脚本和报告，**没有修改生产 app 代码，没有删除任何已有功能，没有修改旧目录，没有调用真实模型**。

因此，本地可证明的是“旧目录参考代码的工具和测量边界”；最初 GitHub 版本与旧模型端到端稳定性仍是未证明项。这些未知不能作为增加重复功能的理由。

## 已确认应复用的能力

### 爱心生成已经存在

旧 `app/agent_skills.py:1628` 定义 `heart_outline_geometry`，旧 `app/cad_project_candidates.py` 已导入并调用它。直接调用已有函数生成4×4米爱心，通过旧可行性、尺寸、闭合和凹口检查。

必须保留限制：语义检查整体为 `partial`，旧独立检查的 `heart_visual_semantics` 仍为false。因此只能证明“已有专用生成工具和部分测量”，不是A1正式交付通过。不能把原链路A1失败归为“原本没有画爱心的能力”；后续也不应再增加同类生成器。是否让现有工具进入正式构造链，应另用来源约束、候选保存与交付证据验证，不能以回退绕过验收。

### S形分割与对称小圆检查已经存在

旧 `app/cad_path_relation_acceptance.py:48` 的 `verify_path_relations` 已检查开放链连接、自交、反向弯曲、圆周端点、外圆内约束，以及对称小圆数量、位置、半径和边界相交；旧解释器已经调用它。

在真实记录的C31计划上，旧检查返回 `partial` 并给出两项测量证据。主要缺口不能概括为“没有S形验收”；应区分完整来源覆盖与几何测量。新增原生圆/圆弧验收重复了部分已有检查，而且支持表达范围更窄，优先整合为旧测量器的来源覆盖适配层。

### 星形线和分支结构已有测量

旧星形线验证器在记录的C18几何上返回 `passed`；旧分支验证器在记录的C22几何上返回 `partial`，包含58项已通过测量。新增加的完整来源消费层有作用，但不应重新实现这些数学恒等式、对称和连接测量。

### SketchGraph / 约束求解与共享点不是相同能力

旧SketchGraph的节点类型是 drawing/object/segment，边关系含 contains/depends_on/connected_to/closes_to；它没有当前新增的坐标点引用语法。旧构造约束提供同心、平行、垂直、等半径、等尺寸和中心距，不是通用顶点符号表或端点重合求解器。

因此共享点不能直接判作同一功能重复；但原构造坐标已支持安全数学表达式，且共享点尚未使C27正式通过。**它对70项的必要性未获证明**，应暂停扩大使用与新增协议，先比较复用原表达式、已有图和约束能力能否完成任务。不能把“增加了语法”当作“证明原能力不足”。

## 后续研发约束

1. 暂停新增生成器、几何原语、案例专用规划和新的并行验收入口。
2. 每项先查本报告对应的旧工具和测量器，提供执行、语义、正式交付三类独立证据。
3. 优先处理已有测量结果的来源绑定、路由选择、确认保存和交付；不把补证据命名成新增几何能力。
4. 新能力立项须给出旧工具的最小失败复现、可排除的调用错误、替代方案对照和复用范围。未知状态不能直接升级为“能力缺失”。
5. 整合现有重复实现时，先证明正反例行为和支持表达范围，防止删除较通用的旧能力。不要为简化代码而放宽验收，也不要保留两个互相矛盾的权威判定入口。
