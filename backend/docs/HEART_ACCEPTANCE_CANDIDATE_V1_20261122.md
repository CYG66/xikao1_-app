# 爱心验收候选规则v1

本轮新增评估侧版本`cad.heart-acceptance-candidate.v1`，实现位于`evaluations/heart_acceptance_candidate_v1.py`。没有修改生产验收、正式交付入口、生成器或原成绩，也没有调用新DeepSeek请求。

## 候选规则的组合方式

复用上一轮独立回放中的单判据替换器，保持原解释器的执行、断言、平滑、对称、尺寸、位置、来源覆盖及置信度门槛，只将未另行指定凹口要求时的固定比例窗口替换为`cad.notch-relation.v1`。

规则对照先运行旧版本，再在单线程隔离上下文中运行候选版本。只有候选解释达到ready、完整验收摘要通过且新旧实际几何完全一致，才输出`candidate_passed=true`。`formal_candidate_accepted`始终为false，不调用提交或保存候选。上下文结束恢复旧验证器；这是离线版本候选，不能在并发服务中临时替换全局函数。

有明确凹口、凹陷、凹槽或notch描述时保守返回`unsupported`，要求后续增加来源测量适配；当前版本不会忽略明确深度或比例，也不会假装已支持其测量。它比单纯识别数值深度更保守，普通显式凹口描述也暂不适用。

## 测试与回放

相关测试**31项通过**：`.local-dev/candidate-rule-final-6wi9r7bi`。包含：

- 两份实际浅凹口计划在候选规则下通过、旧规则仍拒绝，几何不变。
- 最终中央凸起反例仍拒绝。
- 测试中的椭圆、U形和自交轮廓在完整候选中仍拒绝；U形能满足局部关系不等于完整验收通过。
- 明确凹口深度/描述不会套用默认关系，未知附加面积要求仍阻塞完整覆盖。
- 单判据回放结束后恢复原验证器，原规则再次运行仍维持拒绝。

独立报告`.local-dev/HEART_ACCEPTANCE_CANDIDATE_V1_20261122.json`保留新旧结果：历史响应3、5仅候选通过；响应7新旧都失败。报告含夹具、候选实现、依赖规则和旧验证器源码哈希。没有写入旧报告或旧成绩。

这些是同一历史失败运行中的三份计划，不是三次新的真实生成测试。不能把两份候选通过换算成新的A9稳定性、70项通过率或生成能力提升。生产代码没有变化，未重复运行原838项并声称新全量成绩。

## 适用边界与下一步

这是“复用现有全部自动检查、改一个凹口前提”的完整流程候选，仍继承现有形态近似检查和采样测量的局限。31项测试不证明任意轮廓都能被正确分类，也不证明能替代用户视觉判断。

下一步应扩大独立形态正反例及真实计划回放范围，尤其是圆滑U形、多个凹口、单侧凸瓣、轻微不对称和旋转/倒置轮廓，检查规则是否误放行。规则验证充分后再做独立版本的业务验收对照；不得直接把评估模块中的临时函数替换挂到生产服务，也不能删除旧评分口径。
