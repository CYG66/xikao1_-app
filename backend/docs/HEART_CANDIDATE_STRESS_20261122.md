# 候选规则v1扩大反例：发现误放行

本轮仅增加离线压力样例及测试，未修改生产应用、候选规则v1或正式交付入口，未调用DeepSeek。

## 结论

候选v1**暂不能进入生产**。9个负例中，两个不同采样密度的圆滑U形被候选规则误放行；其余7个被拒绝。原规则对全部9个样例仍拒绝。这里的9个是合成测试样例，不是真实模型请求，不是原70条成绩。

| 负例 | 旧规则 | 候选v1 |
| --- | --- | --- |
| 对称圆滑U形，两种采样密度 | 拒绝 | 误放行 |
| 多凸瓣，两种密度 | 拒绝 | 拒绝，尖锐连接 |
| 圆形，两种密度 | 拒绝 | 拒绝，缺少中央凹陷 |
| 倒置轮廓 | 拒绝 | 拒绝，形态不符 |
| 横置轮廓 | 拒绝 | 拒绝，形态不符 |
| 不对称轮廓 | 拒绝 | 拒绝，来源对称要求不满足 |

多凸瓣样例因平滑检查拒绝，不能据此宣称候选已经能识别所有圆滑多凸瓣形态。

## 误放行根因

圆滑U形具有真实的中央凹陷、左右上部和连续边界，能通过新的上部关系检查。原“lower_tip”却只是检查底部中央附近是否存在采样点。平底边加密采样后会出现这样的点，因此它并没有证明底部实际收敛。形状没有变成爱心，只是样本密度让点存在性谓词满足。

独立测试确认圆滑U形无自交、反射对称，且最低位置有超过2米宽的平底。这是有效反例，不能把它解释成数值不对称或尖角造成的拒绝。新上部关系不能单独弥补旧底部谓词缺陷。

因此，前一轮“完整候选”仅表示它走完现有自动检查，不表示这些检查足以保证完整心形语义。本轮反例证实尚需补足底部形态关系。

## 验证和记录

相关测试**34项通过**，`.local-dev/stress-regression-g8pqu3kd`。其中两项明确记录“当前候选存在误放行”的已知缺陷，用于阻止误报规则成熟，并非把U形通过当作正确行为。

最终报告`.local-dev/HEART_CANDIDATE_STRESS_FINAL_20261122.json`保留各负例新旧判定、来源验收、输入哈希，且`promotion_blocked=true`。这只是离线报告状态，不是新增审批流程。

第一版合成样例有两处构造问题：等弧长采样破坏了应有镜像对称；对参数曲线误用了Bezier控制点变换，导致倒置等样例没有真正改变。修正为镜像配对采样、对参数表达式做实际变换，并添加不可原样变换的测试后才得出上述结论。初始无效结果保留在`.local-dev/HEART_CANDIDATE_STRESS_20261122.json`，不能作为误放行证据；修正中间结果另存，未覆盖。

合成曲线只存在于评估脚本`evaluations/stress_heart_candidate_v1.py`中作为负例数据，没有接入后端生成路径。测试有Shapely旧参数的弃用提示，不影响结果。

## 下一步

应先增加可区分“底部中央采样点”与“边界向中央收敛”的独立测量，验证采样密度、圆滑U形、平底、圆底及真实深浅凹口计划，再形成候选v2；保留v1失败样例和原评分。不能仅提高采样密度、排除U形名称或为70条语料添加专用生成器。
