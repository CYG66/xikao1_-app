# 离线候选v3：通过、拒绝、未确定

本轮新增`cad.heart-acceptance-candidate.v3`，只在评估侧组合已有规则和源极值证据。生产应用、正式交付入口、v1/v2及旧成绩均未修改，没有调用DeepSeek。

## 分级逻辑

先运行已有v2并保留完整结果。v1继承检查明确失败时拒绝；不支持或证据未齐的情况保留未确定。前置检查通过后，再按表示类型处理：

- 单源声明多段线：按既有分段直线边界及v2底部关系判定，不为其假设隐藏曲线。
- 受支持的全Bezier闭合轮廓：要求布局映射和源极值可追溯。可分辨的整体最低平段拒绝；极窄平段、多个最低点或无法解决的变换保持未确定。
- 孤立最低点：还要位于中央，且既有底部截面及其他检查通过，才可离线通过。若采样截面失败，即使原曲线有孤立点，也保持未确定，不自动覆盖失败。
- 任意参数式、混合路径、多步骤等尚未支持的原表示：未确定，不能仅凭v2采样通过升级为通过。

输出`decision=passed/rejected/undetermined`，只有第一类对应`candidate_passed=true`；`formal_candidate_accepted`恒为false。不存在把“未确定”当成功的提交路径。

该分级更保守，不表示完全解决采样敏感性。继承的前置形态/平滑检查本身仍有采样和经验阈值局限；本轮主要约束缺少源极值证据时的通过行为，不能据此证明所有拒绝都正确。

## 下一步

v3已明确暴露未支持原表示，后续应优先处理实际历史计划中的参数曲线极值证据，先界定可分析的表达式范围，并复用安全求值、原表达式及现有数值工具。无法可靠证明的表达式继续未确定，不靠扩大容差或偷偷恢复采样默认通过。待候选范围和证据充分后，再讨论版本化业务验收集成，不能把离线临时替换接到并发生产服务。
