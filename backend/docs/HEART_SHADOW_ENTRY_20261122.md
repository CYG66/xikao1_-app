# 显式规则调用与默认关闭的影子评估入口

本轮在新后端加入显式的内部语义验证器参数，并完成评估侧影子入口。默认正式判定仍使用旧规则，没有放宽旧阈值，没有接入设备或提交新候选，也没有调用新DeepSeek API。

## 实现

`verify_semantic_requirements`增加内部可选凹口关系参数；`interpret_construction_request`增加内部可选语义验证器，并将该选择传递到已有诊断和确定性修复递归调用。默认值为空时行为保持旧口径。模型输出和用户自然语言不能设置这些Python内部参数。

评估侧候选现在通过请求局部绑定函数调用明确验证器，不再克隆AST、exec编译或替换模块级验证函数。v1的组合规则逻辑不变，底层调用方式更新；旧报告保存的实现哈希仍代表其当时版本。

新增`evaluations/heart_shadow_entry_v1.py`的`interpret_with_shadow`：

- 默认`enabled=False`，返回与原解释器一致的正式结果，不增加影子字段。
- 开启后先完成旧规则正式解释，捕获本次真实模型输出，再以捕获的输出运行显式v5对照。影子不会再次调用原模型回调。
- 影子数据仅追加到`shadow_acceptance`，不能改写正式status、acceptance_summary或plan。未知规则、无模型计划及影子异常只产生独立报告。
- 所有影子记录声明不影响正式接受，不执行提交。具体候选对照中即使通过，正式失败也维持失败。

入口目前位于评估侧，**尚未连接agent_service或HTTP请求路由**，没有宣称生产请求已自动跑影子。该包装器同步计算影子报告，尚不具备生产延迟隔离或后台调度保证；后续真实评测接入需明确耗时与失败边界，不能直接把它当作线上异步架构。
