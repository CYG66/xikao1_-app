# CAD 前三项验收

固定输入在 `cad_product_acceptance_v1.json`。修改语料应评审差异；报告记录文件 SHA-256，不能通过临时修改期望值消除失败。

包含笑脸、信号灯、三点整时钟、相接但独立的圆和矩形。每例经过描述、补尺寸、确认，再整体右移一米；大范围修改走正常确认流程。没有新增这些对象的专用生成器。

## 执行

在 backend 目录，先通过环境提供有效 DEEPSEEK_API_KEY，再运行：

```powershell
python tests/manual/run_cad_product_acceptance.py --output evaluations/reports/product-acceptance --app
```

此命令先调用真实 DeepSeek 和生产聊天 HTTP handler，再把录制响应通过本地 HTTP 桥送给生产 App 组件。设备通信是虚拟的。前端检查实际发送、自动进入项目、右侧画布、整体/部件/图元点选、选区随修改请求发送、修改后归属及新候选显示。不是平板安装验收，也不是 ROS 执行验收。

增加 `--live-app` 时，App 的生成请求也实时经过 HTTP 桥调用生产 handler 和真实 DeepSeek，不使用录制 CAD 响应。会额外消耗模型调用。

已有记录可加 `--verify-only --app` 重跑验收与 App 回放，不调用模型。`--cases smile clock` 可选择固定子集。失败时命令非零退出，日志保存在各例目录的 `app-test.log`，总结在 `summary.json`；`not_run`、`replay_passed` 和 `live_passed` 明确区分。

## 契约与范围

- 项目需求账本保存逐轮用户原文、来源位置、未确认模型假设、待澄清字段；候选固定需求快照。修改版本保留原来源并追加修改原文，旧坐标验收不直接沿用。
- 通用原文验收目前支持明确标注的部件条款，例如“左眼：圆，圆心(-0.35,0.35)，半径0.09米，坐标单位米”。支持圆、圆弧、轴对齐矩形、线段及显式米/厘米/毫米单位。直接从原文测量位置、尺寸、类型、弧角，一一匹配实际图元，不读取模型自报断言来决定通过。
- 这种条款是当前独立验收的可解析范围，不要求所有用户使用这种写法。普通描述继续可生成，但不能据此宣称未覆盖的语义已验收。外观、任意自然语言部件解析和复杂曲线语义仍为部分覆盖。
- `assembly_id/assembly_label` 记录整体；`object_id/label/geometry_refs` 记录部件与图元。归属随候选、修改、恢复和 JSON 图纸保留。整体选择按声明归属，不按距离、连接或形状名称；缺少声明的旧数据仅用原有兼容逻辑。
- 现有共享边界拓扑保持不变。修改不能静默更换已存在部件的整体归属。

本验收不证明任意文本都被完整理解，不验证第三方 CAD 格式往返，也不证明允许直接施工。模型语义错误、未声明整体的历史图纸及未覆盖需求仍应作为明确限制。

## 第4、5项：恢复证据与持续运行

生产构造入口按缺参、模型计划、采样预算、约束冲突、网络和保存失败分类。几何计划修复最多一次，网络/保存失败不交给模型改几何。`cad.generation-recovery.v1` 保留每次计划、错误、计划哈希和原始输入哈希；成功随构造记录保存，失败随响应返回。`background_job=null` 明确没有隐式后台任务。模型传输层的重试仍是独立层，不能把“一次计划修复”解读成“一次HTTP请求”。

验收命令增加 `--repeat 3`，会在 round-1、round-2、round-3 独立目录运行同一语料。可由现有CI或任务调度执行；未自动创建定时任务。每例失败会留在报告中，继续跑剩余例，最终非零退出。

`metrics.json` 记录通过率、首次计划成功率（有恢复证据时）、请求耗时、已报告token和失败类别。旧记录没有耗时/用量时为 null；成本、漏件率和错误放行率暂不具备可靠观测，保持 null，不能宣传为零。真实模型可靠性需多轮重复，App回放只验证前端行为，不代替模型重复测试。

当前固定语料覆盖多轮补充、多对象、选择、修改，worker逐请求重建会读取已保存项目；尚未完整覆盖项目切换、App进程重启和标注负样本统计。第5项因此是可持续运行基础已接通，并非全部产品回归范围完成。
