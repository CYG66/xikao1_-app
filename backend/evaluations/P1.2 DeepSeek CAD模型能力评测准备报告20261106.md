# P1.2 DeepSeek CAD 模型能力评测准备报告

本轮只完成只读链路检查、样本筛选和零费用预检，**没有调用 DeepSeek，没有修改生产代码，没有运行 70 条全量测试**。

## 1. 当前生产调用链

### 创建

HTTP `/api/agent/chat` → `agent_http_service` 路由 → `RobotAgent.chat` / `_formal_cad_construction` → `interpret_construction_request` → 三类路径：参数化模板、确定性规则、结构化模型 → `cad.construction-plan.v1` → `execute_construction_plan` → 独立几何/语义验收 → `cad_candidate_orchestrator` / `commit_construction_interpretation` → 项目候选版本保存。

`cad_construction_interpreter.py` 中，只有规则、模板和组合契约不能完整覆盖请求时，且传入 `model_callback`，才进入 `structured_model`。模型输出先经过引用修复、扇区/布局/路径连接等有限确定性规范化，再由严格 Schema 和执行器验证。任何未知要求仍保留 `unknown/review_required`。

### 修改

HTTP `/api/agent/chat` → `_prepare_agent_chat_context` → `agent_http_service` 的编辑路由 → `parse_incremental_edit` / 编辑链 / 结构化编辑回退 → `cad.edit.v2` → `incremental_cad.edit_candidate_geometries` 或链重放 → `build_cad_edit_preflight` → 用户确认（高风险时）→ `_execute_confirmed` → `_persist_candidate_edit` → 新版本及来源映射保存。

可解析的平移、旋转、缩放、删除、阵列和部分约束由确定性编辑器处理；无法被确定性编辑器完整解析时才进入结构化编辑模型回退。`cad_target_resolver` 负责版本绑定的选区、逻辑对象和已保存来源映射解析。

## 2. 模型参与条件

零费用调用 `interpret_construction_request(..., model_callback=None)` 对代表性创建语料进行预检。结果表明：

- A9、C7、C16、C31、C34：规则无法完整覆盖，结果带 `model_required`，有合理模型调用预期。
- C1：单独规则入口会澄清控制点/曲线要求；正常结构化构造入口提供模型回调后才是模型候选，需以实际 HTTP 预检确认。
- A11、C10：被组合需求识别器拦截并要求组合参数/确认，不能仅凭函数名推断会调用模型；需在候选项目状态下验证。
- B1：`parse_incremental_edit` 不直接解析，可能进入结构化编辑回退，适合验证“模板关联复制”是否真的调用模型。
- B14：确定性解析器直接返回同心约束，不应计入模型理解测试。
- D3：基础增量解析不直接覆盖多目标旋转，适合进入结构化编辑回退。

## 4. 独立验收判据

每条记录以下独立字段：

1. 模型参与：实际请求数、模型名、finish_reason、usage、原始响应和 Schema 解析结果。
2. 计划有效性：部件是否完整、引用是否存在、步骤是否可执行、尺寸/数量/关系字段是否进入计划。
3. 几何正确性：执行后真实几何的数量、类型、尺寸、中心、边界、闭合、自交、连接、对称及对象归属。
4. 修改正确性：目标 ID/逻辑对象、非目标不变、新版本父子关系、来源映射和版本哈希。
5. 结果分类：`first_plan_pass`、`deterministic_repair_pass`、`model_retry_pass`、`failed`、`clarified`、`review_required`、`blocked`。

不能把模型回复中的“生成成功”、确定性修复成功或 `review_required` 当成正式通过。无法独立判定的要求保持 `unknown/review_required`。

## 5. 零费用预算和日志审计

已有 `tests/manual/deepseek_flash_budget.py` 在请求前保守预留、响应后按真实 usage 结算，并在调用次数、输入/输出 Token、费用、模型名或 usage 不确定时 fail-closed；对应测试已通过。既有账本不可清零：2 次兼容探测、320 输入 Token、38 输出 Token，估算峰值费率费用 `$0.0001416`。

建议本轮新测试硬上限继续使用：最多 32 次累计请求、500,000 输入 Token、128,000 输出 Token、$2；但按 10 条候选估算，首轮每条 1～2 次模型调用，保守预留 20 次请求、约 220,000 输入 Token、80,000 输出 Token，峰值费率约 `$0.16`～`$0.20`，仍需以实际 usage 结算。达到任一上限立即停止。
