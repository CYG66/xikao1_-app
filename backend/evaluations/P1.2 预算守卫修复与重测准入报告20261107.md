# P1.2 预算守卫修复与重测准入报告

本轮只修复评测工具，**没有调用任何真实 DeepSeek API**，没有修改 CAD 生产代码、P0 验收或权限。

## 根因

`run_user_cad_corpus.py` 启动 `cad_widget_live_worker.py` 子进程；worker 内的 `RobotAgentService._deepseek_request` 直接进入供应商请求链，没有经过此前只被 `run_flash_copy_validation.py` 使用的进程内 `Budget`。因此 33 个 `structured_response_received` 事件可以产生，且没有共享请求预留、usage 结算或并发锁。

本轮没有把 33 个响应事件等同于 33 个 HTTP 请求。旧运行的实际 HTTP 数量和费用因缺少逐请求 usage 记录仍不可从旧日志可靠重建；旧目录保持原样。

## 修复位置

- `tests/manual/eval_budget_store.py`
  - 新增持久化 `BudgetLedger`。
  - 使用 Windows `msvcrt` 文件锁（其他平台使用 `fcntl`）保证并发原子预留。
  - 请求前按模型请求 JSON 大小和最大输出 Token 预留额度。
  - 共享账本保存请求数、输入/输出 Token、费用、pending 请求、停止状态和事件。
  - usage、模型或网络结果不可确认时 fail-closed，未返还预留额度。
  - 进程重启继续读取同一账本，不能重置预算。
- `tests/manual/cad_widget_live_worker.py`
  - 在实际 worker 的 `RobotAgentService._deepseek_request` 边界包装预算预留、真实响应结算和逐请求 `model-usage.jsonl`。
  - 每次供应商重试若再次进入该边界，独立消耗请求额度。
  - 支持 `budget_probe` 离线测试入口，使用 Mock provider，不访问网络。
  - 日志只记录模型、请求 ID、finish_reason、usage 和费用，不记录 API Key。
- `tests/test_p12_eval_budget.py`
  - 增加实际 worker 边界的 Mock 测试及并发、上限、重启、unknown usage 场景。

## 离线验证

运行：

```powershell
cd D:\xikao\xikao1_-app\backend
python -m pytest tests/test_p12_eval_budget.py tests/test_deepseek_flash_budget.py -q
```

结果：**12 passed**。

覆盖内容：

- 第 32 次结算后第 33 次预留被拒绝。
- 8 个并发 worker 竞争 4 个额度时只成功 4 个。
- 单次输入/输出/费用超限拒绝发出。
- 实际 usage 与预留不同按实际 usage 结算。
- 缺失 usage 或模型标识停止账本。
- 网络/未知结果不返还额度。
- 重启后读取 stopped 和已用额度，不清零。
- 实际 `cad_widget_live_worker.py` 的 `budget_probe` 经过同一个 `_deepseek_request` 包装；Mock provider 产生 usage、finish_reason 和 `model-usage.jsonl`。
- 非思考模型配置和原有 DeepSeek Flash 预算测试保持通过。

## 账本与旧结果隔离

新的正式评测必须设置独立的 `P12_EVAL_BUDGET_PATH` 和输出目录；历史无效目录 `p1.2-flash-20261106` 未修改。历史兼容探测账本也不覆盖新账本，恢复评测时应显式导入累计起点，而不是删除或重置旧记录。

旧 33 次运行的费用仍不可核算；本轮没有擅自估算或补造费用。

## 重测准入

预算守卫和逐请求日志现在具备重测条件，但正式 10 条评测仍未运行。本轮停止在离线修复阶段，未自动恢复付费评测。下一轮运行前必须：

1. 为新的 `run_user_cad_corpus.py` 运行设置独立账本并从历史累计用量导入起点。
2. 确认每个 worker 都继承同一 `P12_EVAL_BUDGET_PATH`、run_id 和模型配置。
3. 检查首个 Mock `model-usage.jsonl` 与预算账本一致后，才可执行新的真实评测。
