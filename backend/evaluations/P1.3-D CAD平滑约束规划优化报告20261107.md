# P1.3-D CAD 平滑约束规划优化报告

本轮完成只读核查和离线回归，**没有调用 DeepSeek，也没有修改生产代码**。

## 现有能力核查

当前 CAD 结构化提示已明确区分：

- C0 只表示端点位置连续。
- C1 需要可验证的一阶切线关系。
- 平滑重复轮廓优先使用单周期 Bezier，并设置 C1。
- 非重复曲线若未精确证明一阶导数关系，使用 C0，不能虚假声明 C1。
- 尖角轮廓不得声明 C1；合法尖点不能被强行平滑。

`AddCompositePathStep` Schema 已支持 `continuity=C0/C1`、`tangent_tolerance_deg` 和 `max_curvature`。执行器会生成 `cad.curve-quality.v1`，检查切线、曲率、自交、重复段和采样误差。`normalize_composite_path_connections_once` 还会拒绝没有用户依据的 C1 假设，避免把模型臆测变成硬约束。

## A9 诊断

A9 原始需求中的“平滑”进入了模型提示和原文证据，但模型输出的 4 段 Bezier 仅声明 C0。执行器按计划执行，没有丢失已有 C1 字段；当前计划本身没有表达 C1 或 G1 要求。

离线回放结果仍为：C0 通过、C1 失败 2/4 个连接点、最大切线角差约 107.94°。爱心下尖点属于允许的设计尖点，但计划没有结构化标注哪些点允许尖锐，因此不能自动豁免普通接缝，也不能安全把 C0 改成 C1。

## 为什么本轮不修改代码

目前不存在明确的通用传递缺口：

1. 规划协议能表达 C1。
2. 提示词已经说明 C0 不等于平滑。
3. 执行器能验证 C1 并返回具体失败证据。
4. 现有局部修复没有安全的控制点调整能力。

把“平滑”无条件映射成 C1 会错误处理爱心尖点、五角星和机械折角；把旧 A9 计划的 C0 字段改写成 C1 则属于伪造模型输出，且会使执行器拒绝而不会改善几何。因此没有实施生产修改。

## 离线验证

执行相关构造、语义、解释器和提交回归：**141 passed**。

Mock/Schema 现有能力已覆盖：C0 连接、C1 连接、C0 非 G1、闭合接缝、曲率、自交、合法尖点和非零中心。A9 旧计划保持原样，仍应为 `partial`，不能冒充真实模型质量提升。

## 结论与后续建议

本轮确认问题属于**模型没有遵守已有规划协议**，不是协议或执行器缺失。下一步若要提升首次规划质量，建议只做一次小范围真实 DeepSeek 重测，检查模型是否在新提示下将“平滑”表达为合适的 C1/G1 计划；如果仍反复输出 C0，再考虑增加通用“平滑要求未落入计划”的有限反馈，而不是直接改写计划或新增几何修复器。
