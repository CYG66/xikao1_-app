# P1.3-E-R 评测预算绕过最小修复报告

本轮只修复评测上下文传递和 fail-closed，**没有调用真实 DeepSeek，也没有修改 CAD 生产代码**。

## 根因

`run_user_cad_corpus.py` 只依赖父进程偶然继承环境变量；手工启动 S1 worker 时没有设置 `P12_EVAL_BUDGET_PATH`，而 worker 没有显式评测模式，也允许继续初始化生产模型路径。结果 S1 真实请求绕过共享账本。

## 最小修复

- `run_user_cad_corpus.py`：启动评测时显式设置 `P12_EVAL_MODE=1` 和 `P12_EVAL_RUN_ID`，并在启动前校验 `P12_EVAL_BUDGET_PATH` 存在；缺失即拒绝启动。
- `cad_widget_live_worker.py`：评测模式下预算路径缺失立即退出；预算账本初始化后再次确认评测上下文有效。worker 不会静默切换为普通生产调用。
- `tests/test_p12_eval_budget.py`：增加缺预算路径时真实 worker 0 请求测试。

没有创建第二套预算系统，没有改动 CAD Agent、DeepSeek 提示词、P0 权限或生产模型配置。

## 离线回归

运行预算及 worker 测试：**13 passed**。

覆盖：共享账本、并发预留、usage 缺失、重启恢复、Mock worker 调用、评测模式缺预算路径零请求，以及原有 Flash 预算守卫。

缺预算路径测试确认：worker 在任何模型请求前返回 `evaluation_budget_unavailable`，不创建 usage 日志，不访问外部网络。

## 历史证据

此前 P1.3-E A9/S1 中止目录、S1 未核算请求和旧预算账本均未修改。S1 的真实请求仍标记为 unknown，不被重算为 0。

## 重测条件

评测启动器现在要求显式 `P12_EVAL_MODE=1`、`P12_EVAL_RUN_ID` 和共享 `P12_EVAL_BUDGET_PATH`。A9、S1 重新启动时必须由同一 runner 注入这些变量，并用新账本运行；本轮没有自动重跑真实测试。
