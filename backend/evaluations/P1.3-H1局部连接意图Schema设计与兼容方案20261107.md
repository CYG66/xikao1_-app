# P1.3-H1 局部连接意图 Schema 设计与兼容方案

本轮仅完成设计，不修改生产代码、Schema、提示词、验收规则或 P0 权限，不调用 DeepSeek。

## 1. 现有 Schema

`AddCompositePathStep` 当前有 `segments`、`closed`、`connection_tolerance`、整体 `continuity`、`tangent_tolerance_deg`、曲率和自交字段。执行器通过段数组相邻关系生成 `joint_diagnostics`。当前没有局部 junction 字段、稳定 segment_id 或尖点意图。

## 2. 推荐增量字段

在 `AddCompositePathStep` 增加可选字段：

```json
{
  "junction_constraints": [
    {
      "junction_index": 0,
      "left_segment_index": 0,
      "right_segment_index": 1,
      "intent": "smooth",
      "required_continuity": "G1",
      "tangent_tolerance_deg": 1.0,
      "source_requirement_refs": ["source-1"]
    }
  ]
}
```

字段：

- `junction_index`：计划内连接序号。
- `left_segment_index`、`right_segment_index`：前后段索引。
- `intent`：`smooth | intentional_cusp | intentional_corner | unknown`。
- `required_continuity`：`C0 | G1 | C1`。
- `tangent_tolerance_deg`：可选，默认沿用 step 全局值。
- `source_requirement_refs`：复用现有 requirement fact/source ID。

第一版不增加 segment_id，不修改 geometry 字典，不修改 object identity。

## 3. 引用与闭合规则

开放曲线：`right_segment_index == left_segment_index + 1`，junction_index 按数组顺序从 0 开始。

闭合曲线：最后一段到第一段使用 `left=n-1,right=0`，junction_index 为 n-1。其坐标和切线沿用现有闭合接缝计算。

多条复合曲线：每个 `add_composite_path` 步骤独立拥有 `junction_constraints`，不跨步骤引用。

非法情况必须拒绝计划：越界、左右段相同、非相邻、重复同一 junction、引用与 `closed` 不匹配。归一化阶段不得重排 segments；若未来必须重排，必须同时返回旧索引到新索引映射，否则拒绝局部约束计划。

索引只在该 construction_plan 内有效，不是跨版本稳定身份，也不使用坐标相近猜测身份。

## 4. 意图与连续性语义

### smooth

必须有原始需求来源。允许 G1 或 C1；明确“C1/一阶导数连续”时只能使用 C1。实际验收分别检查位置、方向和一阶导数，不能凭声明通过。

### intentional_cusp

至少 C0，允许方向突变；必须有用户原文或可靠结构语义来源。模型单独声明不能获得豁免。实际几何仍需验证连接位置和尖点证据。

### intentional_corner

至少 C0，允许设计折角；必须有明确折角/机械转角来源，不把普通失败接缝自动归为 corner。

### unknown

不提供豁免，不计自动通过；保留 `partial/review_required`，必要时澄清。

G1 只比较切线方向；C1 还需比较未归一化一阶导数向量。参数化速度不一致时只能报告 G1，不能报告 C1。

## 5. 全局与局部优先级

1. 有合法、来源可验证的局部约束：该 junction 使用局部要求。
2. 未被局部覆盖的 junction：沿用 step 全局 `continuity` 和容差。
3. 无局部、无全局：保持现有默认/未知行为。
4. 局部约束与原始需求冲突：拒绝或标记 unknown，不采用模型声明覆盖用户原文。
5. 缺少 `source_requirement_refs` 的 cusp/corner：转为 unknown，不得豁免。

旧计划没有 `junction_constraints` 时，执行和验收路径完全保持现状。

## 6. 需求来源绑定

复用 `cad_requirement_contract` 的 source/fact ID，不新增 requirement ID 系统。`smooth` 绑定含“平滑/切向连续/C1”的原文事实；cusp 绑定“尖点/尖角/尖端”等明确事实或已验证结构契约；corner 绑定明确折角语义；unknown 保留缺失来源状态。

来源引用不存在、指向不匹配或同一来源被用于不相容意图时，计划校验失败。

## 7. 旧版兼容示例

1. 旧单段圆/矩形计划：无该字段，完全不变。
2. 旧 A9 计划：整体 `continuity=C0`，无局部字段，仍得到原有 joint diagnostics 和 partial。
3. 旧 S1 计划：整体 `continuity=C1`，无局部字段，仍按全局 C1 验收。

## 8. 新版示例

1. 两段普通曲线：junction 0，`smooth/G1/source-1`。
2. 全局 C1、局部下尖点：某 junction `intentional_cusp/C0/source-2`，其余未覆盖点仍执行全局 C1。
3. 闭合机械轮廓：末段→首段 `intentional_corner/C0/source-3`，其他连接点 `smooth/G1`。

## 9. 需要修改的模块（H2～H4）

- H2：`cad_construction.py` 增加可选模型、索引校验和局部优先级解析；扩展现有 `joint_diagnostics`，不改旧字段。
- H3：`cad_construction_interpreter.py` 与需求契约绑定来源、验证模型引用；提示词仅增加通用局部约束说明。
- H4：扩展 source acceptance/acceptance summary 和离线回归，验证旧计划、新局部约束、闭合接缝、unknown 与非法引用。

## 10. 关键回答与风险

- 第一版不需要稳定 segment_id；计划内索引足够，但只在单个 plan 版本内有效。
- 不需要修改 geometry 字典或对象身份体系。
- 不需要修改版本存储语义；可将约束随 construction_record 保存。
- 通过可选字段和旧路径分支避免旧计划行为变化。
- 主要风险是模型声明尖点但缺少来源，以及参数化速度不一致导致 G1/C1 混淆；两者必须 fail-closed。

本轮停止于设计阶段。下一步应先实施 H2 的 Schema/索引校验，再实施 H3 来源绑定，最后实施 H4 验收与回归；不应在 H2 前修改真实模型测试或开发控制点自动修复器。
