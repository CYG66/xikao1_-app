# P1.3-H3-R0 真实 HTTP 会话来源上下文只读审计报告

本轮只读审计，未修改代码、未调用 DeepSeek。

## 真实入口

- 创建和编辑请求进入 `routers/agent.py` 的 `/api/agent/chat` 或 `/api/agent/chat/stream`。
- 两者调用 `agent_http_service.agent_chat` / `agent_chat_stream`，再进入 `RobotAgentService` 的路由准备和 `_formal_cad_construction` / 编辑执行路径。
- `conversation_id` 通过 `AgentChatRequest` 进入 `conversation_memory.context/observe`，并参与项目、候选导航和待确认命令绑定。
- `project_id`、`variant_id`、`drawing_selection` 在 `agent_http_service` 中进行当前项目/版本和选区绑定检查；项目快照由 `get_creative_project_store()` 读取。

## 五个核心标识现状

| 标识 | 真实链路结论 |
|---|---|
| conversation_id | 已进入 HTTP、memory、route 和待确认绑定；未发现 H3 来源索引在 HTTP 层持久化绑定。 |
| project_id | 真实项目仓库解析并参与编辑绑定；创建路径可由服务端新建项目。 |
| variant_id | 当前候选及父版本在编辑/确认路径校验；创建路径由候选提交生成。 |
| request_id | 现有 agent run/audit 体系记录请求，但 `build_requirement_source_index` 当前调用点没有从真实 HTTP 请求注入稳定 request_id。 |
| contract_version | 当前来源索引函数可生成哈希版本，但真实 HTTP 会话没有证据证明该版本被持久化并随异步/确认请求传递。 |

## H3/H4 实际接入边界

`cad_construction_interpreter.py` 已在结构化模型规划前构造来源索引，并在模型计划返回后校验 `junction_constraints.source_requirement_refs`。H4 由 construction executor 消费局部约束。

但该来源索引目前由解释器按 `original_requirement` 临时构造，使用 `user:{index}` source id；HTTP 层的 conversation/project/variant 上下文没有作为不可变快照传入来源索引。`inherit_requirement_source_index` 目前是可调用 helper，没有在 `agent_http_service` 的每个真实请求入口形成持久化绑定。

因此不能宣称完整闭环：真实 HTTP 路由到 H2/H3/H4 的几何计划链路存在，但 H3.3 的会话、项目、版本、request_id、contract_version 绑定尚未完整贯通。

## 主要风险

1. 多轮确认/补参可能在不同请求中重新生成来源索引，无法证明旧来源属于当前 contract_version。
2. 项目切换后，conversation memory 有绑定检查，但来源索引本身没有同等 project_id/version 证据。
3. 异步/恢复入口可以恢复项目和候选，但当前审计未找到来源索引快照随恢复请求传递的证据。
4. H4 使用的是经过解释器校验的局部约束，但缺少 HTTP 级来源快照审计字段。

## 结论

当前状态是：**CAD HTTP 创建/编辑、项目/版本绑定和 H2/H3/H4 独立调用存在；H3.3 真实会话来源隔离尚未证明完整接入。**

下一步最小改造应在 `agent_http_service` 请求上下文准备处生成不可变 contract/source snapshot，并将 request_id、conversation_id、project_id、variant_id、contract_version 一并传入解释器；确认、恢复和异步 worker 必须复用该快照。完成前不应进行宣称 H3-R 真实端到端通过的测试。
