# P1.3-H3-R3 A9 第一轮验收证据缺口诊断

## 结论

历史 A9 第一轮不是几何执行失败。实际几何、宽高和中心检查均通过；正式候选被阻止的直接原因是验收证据对象没有把完整覆盖状态提升为 `passed`，最终候选状态因此为 `review_required`。

## 已具备证据

- Requirement Ledger 保存了原始用户来源和宽高事实。
- construction plan 使用 `add_parametric_curve`，闭合且有明确宽高、中心布局。
- 几何断言：`closed`、`bounds_size` 均通过。
- constraint solver：无约束残差失败，几何为 authoritative。
- graph validation：通过，1 个逻辑对象、无关系错误。
- final source acceptance 中 width、height、center 三项均为 passed。
- 语义检查 `heart_bilateral_lobes_notch_and_lower_tip` 已通过。

## 缺失或未闭合证据

1. Requirement Ledger 的语义来源仍显示 `coverage: partial`，平滑、闭合、对称和尖点等原文要求没有全部形成可回溯的 bound requirement records。
2. `source_acceptance` 顶层仍是 `status: not_checked, coverage: partial`，虽然内部 `final_source_acceptance` 已有尺寸和中心检查，但没有被统一汇总状态消费。
3. `semantic_acceptance` 内部检查通过，但整体仍为 `partial`；平滑连接的独立证据没有形成可验证的局部连接记录。
4. `construction_acceptance_summary` 因 source acceptance 顶层未通过，将 `requirement_coverage` 设为 unknown，并生成 `review_required`。

## 归因

这是三类问题中的第二类：**现有验收证据汇总没有完整覆盖所有语义要求**。它不是模型计划缺少几何，也不是执行器生成错误；当前记录显示几何本身满足已支持的宽高、中心、闭合和爱心轮廓检查。

本诊断不建议放宽候选权限，也不建议直接把 `status` 改为 passed。应分别保留：已验证的几何事实、未绑定的语义来源、尚未证明的平滑连续性。

## 对真实模型测试的影响

A9 即使保持 `review_required`，仍可用于单轮 DeepSeek 能力评测：模型响应、计划、实际几何、H3 来源引用和 H4 结果均可独立统计。正式候选生命周期测试应另用完整来源证据夹具，不应阻塞真实模型评测。

本轮为只读诊断，未调用 DeepSeek，未修改生产代码。
