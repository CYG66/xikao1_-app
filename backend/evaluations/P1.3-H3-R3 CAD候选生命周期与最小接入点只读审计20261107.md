# P1.3-H3-R3 CAD 候选生命周期与最小接入点只读审计

## 结论

当前 CAD 不使用机器人 `pending_action -> /confirm` 作为正常生成路径。真实生产路径是：

`/api/agent/chat` → `agent_http_service.agent_chat` → `RobotAgentService._formal_cad_construction` → `interpretation` → `commit_construction_interpretation` → `persist_candidate_variant` → 项目 `variants` → App 预览/选择。

因此不应把 CAD 构造伪装成运动确认任务。

## 实际生命周期

1. `_formal_cad_construction` 在构造计划通过独立验收后直接调用 `commit_construction_interpretation`。
2. `cad_construction_commit.py` 重新执行最终 construction plan，并将最终几何交给 `persist_candidate_variant`。
3. `persist_candidate_variant` 将候选写入当前项目的 `variants`，保存 parent variant、acceptance summary、logical objects、topology、edit metadata 等。
4. 返回结果中的 `next_action` 为 `select_design_variant`，说明 CAD 用户确认语义是“预览/选择候选”，不是设备执行确认。
5. `/api/agent/projects/{project_id}/select-variant` 是现有候选选择入口；`/start-iteration` 是现有编辑基线入口；自然语言第二轮由 `agent_http_service` 根据项目、选区和当前版本进入编辑路由。

## 草稿与正式候选

- `draft_preview` 由 HTTP 响应层独立生成，不能替代候选版本。
- 正式候选必须经过 `persist_candidate_variant` 和统一验收状态判断。
- 待复核草稿可以预览，但不能通过选择或施工权限入口。

## 已确认的最小接入缺口

`_prepare_agent_chat_context` 已生成不可变 `execution_context`，并由 HTTP 响应和 run checkpoint 保存。但 `_formal_cad_construction` 调用 `commit_construction_interpretation` 时没有将该快照作为 `candidate_metadata` 传入；因此候选版本目前不会稳定保存请求上下文、来源索引和 contract_version。

这是 H3-R3 的最小生产接入点：在现有候选元数据字段中保存快照，不新增确认系统，不改变候选权限。

## 第二轮编辑

第二轮请求通过 `drawing_selection.project_id + variant_id` 和项目的 `selected_variant_id/design_base_variant_id` 定位基线；`_persist_candidate_edit` 通过 `parent_variant_id` 保存新版本，并保留原版本。需求来源应从持久化项目需求契约和版本元数据继承，再由 H3 校验后交给 H4。

当前需要补证：

- 第一轮 execution_context 是否进入 variant metadata；
- 第二轮是否生成新的 request_id/contract_version，同时保留来源链；
- 局部 junction_constraints 是否确实经过 H3 来源校验后进入 H4 验收。

## 审计结论

1. 不需要新增 CAD `/confirm`；
2. 不需要复制机器人 pending_action；
3. 最小接入应位于 construction commit 的候选元数据传递；
4. 完成该接入后，再用真实 FastAPI Mock 验证创建、候选选择、第二轮编辑和版本连续性；
5. 在此之前不应声称 H3-R3 已闭环，也不应开始真实 DeepSeek A9/S1 重测。

本轮为只读审计，未修改生产代码、提示词、Schema、P0 权限或历史测试数据。
