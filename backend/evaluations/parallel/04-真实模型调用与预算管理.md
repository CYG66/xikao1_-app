# 真实模型调用与预算管理

四线并行最容易失控的不是代码冲突，是**四条线各烧各的 token，最后既算不清账，也无法归因**。本文件规定唯一入口。

## 一、唯一入口

- 真实 DeepSeek 调用**只能**由 D 通过统一运行器发起，运行器位于 `backend/evaluations/parallel/bench/`（由 D 建立）。
- A/B/C 可以做：Mock、录制回放、离线几何复算、只读历史请求。**不得**自己写脚本直连模型。
- A 若需要"看模型真实输出"，向 D 提运行申请（案例清单 + 目的 + 预估调用数），由 D 跑完回传原始响应。
- 运行器必须自带开关：未显式开启（建议环境变量 `CAD_PARALLEL_REAL_MODEL=1`）时，一律走 Mock，拒绝真实网络请求。

## 二、预算账本

- 文件：`backend/evaluations/parallel/budget-ledger.jsonl`，一行一次调用，只追加不覆盖。
- 必填字段：

| 字段 | 说明 |
|---|---|
| `ts` | ISO 时间 |
| `line` | `evaluation` / `nlp` / `geometry` / `orchestration`（申请方） |
| `case_id` | 案例编号，必须来自冻结清单或 D 的新增注册表 |
| `model` | 模型标识 |
| `policy` | 策略/提示词版本标识 |
| `request_id` | 上游返回的 request id，原样保存 |
| `prompt_tokens` / `completion_tokens` | usage 原值 |
| `finish_reason` | 原值 |
| `cost` | 计费口径与金额（写明单价来源） |
| `outcome` | `pass` / `fail` / `error` / `truncated` |
| `artifact` | 原始响应落盘路径 |

- request_id 与原始响应必须成对保存；只有金额没有 request_id 的记录视为无效。

## 三、调用纪律

1. **案例隔离**：一次运行只跑一个案例集，不混跑 A9 与新增案例。
2. **不重复跑**：同一 case + 同一 policy + 同一模型，已有记录则复用，不重复计费。
3. **上限熔断**：单次运行设调用数与金额上限，达到即停并写"熔断记录"；不允许"再试一次应该能过"。
4. **失败也记账**：超时、截断、审核拒绝同样写账本，`outcome` 如实标注。
5. **温度与随机性**：评测用固定温度与固定 seed（若模型支持）；不支持则在报告里说明不可复现的部分。
6. **不在生产库上跑**：真实调用产生的候选只写临时项目，不写用户项目。

## 四、准入检查（每次真实运行前逐项打勾）

- [ ] 本次目的能用一句话说清，并对应到 `05` 的某个指标。
- [ ] 案例清单已冻结，输入未被修改。
- [ ] 运行器开关显式开启，且上限已设。
- [ ] 账本文件可写，路径正确。
- [ ] 上一次运行的账已结清（无未写账本的调用）。
- [ ] 运行结束后会回传：原始响应 + 账本增量 + 结论。

## 五、谁能授权

- 单次 ≤ 20 次调用：D 自行执行并记录。
- 单次 > 20 次或涉及金额上限调整：需用户明确同意。
- 任何一条线绕过 D 直接调用：该线本轮结论作废，按 `02` 打回。

## 六、报告里必须区分来源

所有结论标注证据等级：

| 等级 | 含义 |
|---|---|
| E1 | 真实模型 + 真实执行链 + 冻结案例 |
| E2 | 真实模型 + 离线执行（只验规划或只验几何） |
| E3 | Mock/录制回放 |
| E4 | 静态分析/代码推理 |

没有 E1/E2 证据的"效果提升"只能写成假设，不得写进结论段。
