# 考核指标口径

从本轮起，不以"完成了多少个 P1.x 阶段"作为进度，而以三个实际结果作为验收对象。四条线共同服务于这三个数，而不是各自交付一个模块。

## 指标一：首次生成成功率（FSR）

**定义**：一次生成（无人工干预、无重试、无澄清）即同时通过 H2（几何合法）、H3（来源可追）、H4（局部约束生效）的案例数 / 参与案例数。

- 分子判定：三态全通过才算通过；任一失败即失败，不得"部分通过"折算。
- "一次"的口径：同一 `request_id` 内不再发起第二次模型调用；链路内部的确定性重试（不重新问模型）不算重试。
- 分母：本轮参与评测的案例集合，必须写明清单与数量。

## 指标二：复杂几何质量（CGQ）

**定义**：在通过 H2 的案例中，出现以下任一缺陷的案例占比，越低越好：

1. 非相邻段自相交（`allow_self_intersection=False` 时仍相交）。
2. 连接点连续性不满足声明的 `intent`（`smooth` 却不足 G1 等）。
3. 端点拼接误差超过 `connection_tolerance`。
4. 曲线离散误差超过 `max_sampling_error`。
5. 尺寸/面积断言偏差超出计划 `assertions` 的容差。

- 必须同时报"缺陷类型分布"，只报总分无法定位问题。
- 指标二的分母是"通过 H2 的案例"，不是全部案例；两个指标不可互相替代。

## 指标三：多轮编辑成功率（MES）

**定义**：在已有一轮结果的基础上，第二轮自然语言编辑一次通过（含来源继承 H3.3 与局部约束传递 H3.4）的会话数 / 参与会话数。

- 必须验证三件事：编辑对象身份正确、来源继承正确、最终落库版本正确。
- "通过"包括不得产生孤儿版本、不得残留半成品。
- 第三轮及以后单独统计，不计入本指标（避免用长会话稀释）。

## 基线记录要求

任何优化开始前，先在 D 的工作树里记录一次**未改动代码**的基线：

| 字段 | 要求 |
|---|---|
| 基线 commit | `211cacd` 或集成起点 |
| 案例清单 | 案例 id + 输入哈希 |
| 每次调用 | 账本条目（见 `04`） |
| 结果 | 每案例的三态矩阵（H2/H3/H4） |
| 环境 | Python 版本、依赖版本、模型标识、温度 |

## 关于样本量的诚实说明

- 当前冻结案例只有 A9、S1、M1 三个，**任何以百分比表述的"提升"都没有统计意义**。
- n < 5 时只报逐案例三态矩阵（通过/失败）与缺陷计数，不报百分比、不写"提升 X%"。
- 要报比例，先把案例扩到 ≥10 且覆盖至少三类几何（闭合曲线、机械折角、多对象布局），并说明扩样规则。

## 判定"本轮有效"的最低门槛

同时满足才算有效：

1. 指标一在冻结案例上不退化（A9/S1/M1 至少保持原状）。
2. 指标二或指标三至少一项有**可复现的**改善（附命令与原始输出）。
3. 没有用放宽阈值换来的通过（回归清单第 2 项与第 9 项均通过）。
4. 结论段只使用 E1/E2 证据（见 `04` 的证据等级）。

## 反面清单（出现任一条即视为"假进展"）

- 只改提示词让模型"看起来更听话"，但几何验收仍失败。
- 只改测试断言让结果变绿。
- 只在 A9 上生效、换案例即失效（过拟合）。
- 只报通过项，不报失败项与未验证项。
- 用"链路已打通"替代"结果正确"。

## 进度口径（替代 P1.x 编号）

从本轮起，**不再用 P1.5 / P1.6 这类阶段编号作为进度指标**。阶段编号只用于给提交和文档归档，不用来汇报"完成了多少"。

四条主线各自的交付目标：

| 主线 | 自己的考核对象 | 落到哪个核心指标 |
|---|---|---|
| A NLP/Planning | 自然语言理解质量、首次规划质量 | 指标一（FSR） |
| B Geometry | 几何正确率、自相交率、约束满足率 | 指标二（CGQ） |
| C Orchestration | 创建 / 保存 / 多轮修改成功率 | 指标三（MES） |
| D Evaluation | 评测可信度、失败归因准确性、回归覆盖 | 支撑上述三项的可信度 |

四条线共同服务于三个数：**首次生成成功率、几何约束满足率、多轮编辑成功率**。

汇报时的硬规则：

1. 说"这轮做了什么"，必须同时说"这三个数有没有动、动了多少、证据等级是什么"。
2. 三个数都没动，就必须说明"为什么这轮值得做"（例如消除阻塞、补齐证据），否则该轮记为无产出。
3. 阶段编号不再是验收对象；`P1.4` 只是本轮的归档标签。
