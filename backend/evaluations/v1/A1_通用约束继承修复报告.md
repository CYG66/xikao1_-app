## 2. 缺陷根因

### 2.1 合并层整步替换

生产链路的实际合并点是 `backend/app/cad_plan_component_repair.py` 的 `merge_component_repair()`。

修复前，普通部件修复分支只把原步骤的以下字段写回 replacement：

- `step_id`
- `output_ref`
- `semantic`
- `layer_id`

随后整步替换。replacement 未携带的字段会丢失或退回 Schema 默认值，包括：

- `junction_constraints`
- `continuity`
- `tangent_tolerance_deg`
- `closed`
- `samples_per_curve`
- `connection_tolerance`
- `allow_self_intersection`
- `allow_duplicate_segments`
- `max_curvature`
- `max_sampling_error`

### 2.2 模型协议未明确要求保留约束

`backend/app/agent_service.py` 的 `_interpret_cad_construction_plan()` 在局部修复时只告诉模型“只输出受影响步骤、其他由后端保留”，没有明确要求保留失败步骤原有的连接约束和执行策略。模型容易按 Schema 默认值输出 `junction_constraints: []`，从而触发清空。

### 2.3 明确错误被通用异常吞掉

`backend/app/cad_construction_interpreter.py` 的 `interpret_construction_request()` 对模型回调使用宽泛的 `except Exception`。如果合并层抛出明确的约束映射错误，会被统一转换成 `invalid_model_output`，上游无法看到具体错误码。

## 3. 修复内容

### 3.1 `cad_plan_component_repair.py`

新增 `ComponentRepairError(ValueError)`，携带稳定的 `code` 和 `details`，用于单元测试与服务级链路断言。

新增通用合并语义：

1. 缺失字段继承：replacement 未提供的执行策略字段，从原步骤继承。
2. 显式 `null` 拒绝：非可空策略字段显式 `null` 返回 `component_repair_null_field`；`junction_constraints: null` 返回 `junction_constraints_null_rejected`。
3. 显式清空拒绝：原步骤 `junction_constraints` 非空时，replacement 显式 `[]` 返回 `junction_constraints_clear_rejected`。
4. 部分替换拒绝：段结构未变时，replacement 只提交部分原约束，返回 `junction_constraints_partial_replacement_rejected`。
5. 结构变化保护：段数量变化、段类型序列变化、完全相同的段集合发生顺序变化时，不能沿用旧索引；未提供新约束集合则返回 `junction_constraint_mapping_unsafe`。
6. 索引重新校验：约束必须指向相邻段；开放路径不能声明首尾连接；`junction_index` 必须等于左段索引；同一连接点不得重复；连续性、意图、切向容差必须在 Schema 允许范围内。
7. 显式放宽拒绝：`tangent_tolerance_deg`、`connection_tolerance`、`max_curvature`、`max_sampling_error` 不能放大；`allow_self_intersection`、`allow_duplicate_segments` 不能从 `False` 改为 `True`。
8. 合法变更保留：模型显式提供更严格的容差、合法的 `continuity` 变更、或与新段结构匹配的完整新约束集合时，合并层接受，但仍由下游 H4/来源验收重新判定。
9. 来源不伪造：`junction_constraints` 的 `source_requirement_refs` 不在合并层校验或升级，H3 仍是唯一来源授权入口。
10. 普通图元不受影响：没有连接语义的普通图元修复保持原有行为；若更换构造操作且原步骤有连接语义，返回 `component_repair_op_change_requires_replan`。

### 3.2 `cad_construction_interpreter.py`

在通用异常分支前增加 `except ComponentRepairError`，把 `code`、`message`、`details` 原样写入 `construction_error`，避免明确错误被吞成 `invalid_model_output`。

### 3.3 `agent_service.py`

只在局部修复协议中增加一段通用约束保护说明：

- 保留失败步骤原有的 `junction_constraints`、`continuity`、`tangent_tolerance_deg` 等有效约束；
- 不得清空或放宽；
- 若改变段结构，必须输出与新段结构匹配的完整连接约束集合。

没有修改修复循环、HTTP 多轮、版本管理或其他新功能。

### 3.4 测试与探针

- 扩展 `backend/tests/test_cad_plan_component_repair.py`。
- 新增 `backend/evaluations/v1/probes/a1_constraint_repair_probe.py`，零费用复现合并前后的约束保留与错误码。

## 7. 残余风险与未覆盖项

1. D0 诊断探针 `d0_geometry_probe.py` 的 `junction_repair_probe()` 使用了 Schema 不合法的约束字段（缺少 `junction_index`，`intent` 为 `smooth_connection`）。A1 的严格校验会把它作为无效约束拒绝，而不是返回“字段保留”结果。该探针保留为历史诊断资产，不作为 A1 回归依据；A1 的新探针使用合法夹具，已给出可复现证据。
2. 没有稳定段 ID 时，“同类型段同时重排 + 重写几何”与“原位几何修复”无法完全区分。当前已能检测段数量变化、段类型序列变化、完全相同的段集合重排；若未来需要更强的重排检测，应在 Schema 增加稳定段 ID，而不是在合并层猜测。
3. `junction_constraints` 的来源授权仍由 H3 执行；A1 只保护字段不被丢失，不改变来源验收标准。
4. 本轮服务级验证使用 Mock 模型响应，未调用真实 DeepSeek；真实模型在多次重试下的行为仍需在后续 D1 或获授权联调中验证。
