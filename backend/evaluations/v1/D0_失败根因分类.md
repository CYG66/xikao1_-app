# D0 失败根因分类

## 1. 分类口径

本文件只记录 D0 基线上实际出现、可定位或明确未验证的问题。状态词与 `evaluation_schema.json` 一致：

| 状态 | 含义 |
|---|---|
| `passed` | 在指定证据范围内执行并通过 |
| `failed` | 在指定证据范围内执行并失败 |
| `not_run` | 没有执行，或缺少可执行输入 |
| `unknown` | 有部分证据，但无法判断 |
| `not_checked` | 明确未检查该维度 |
| `collection_blocked` | pytest 收集阶段被阻断，未进入执行 |
| `environment_blocked` | 环境或运行器阻断，不是产品断言失败 |

证据模式严格区分：

| evidence_mode | 本文件中的用法 |
|---|---|
| `reconstructed_fixture` | 用仓库已知控制点或冻结验收重建，不是历史原始响应 |
| `mock` | 纯函数或测试替身，不访问模型 |
| `rule_parser_zero_cost` | 确定性规则解释器，不是端到端 |
| `historical_report` | 历史 Markdown 报告，只作线索 |
| `live_model` | 真实模型调用；D0 未使用 |
| `unavailable` | 原始响应或冻结定义不存在 |

## 3. 逐项说明

### F-01 仓库缺失 `tests/manual/`

**证据**

- `backend/.gitignore:24` 明确忽略 `tests/manual/`。
- 当前 `backend/tests/manual/` 不存在。
- 全量 collect 得到 `1636 tests collected, 8 errors`。
- 8 个模块中 6 个抛 `ModuleNotFoundError: No module named 'tests.manual'`，2 个抛 `FileNotFoundError`，根因同为缺 `tests/manual/` 下的具体文件。

**受影响模块**

| 模块 | 缺失目标 |
|---|---|
| `tests/test_cad_acceptance_metrics.py` | `tests.manual.cad_acceptance_metrics` |
| `tests/test_cad_corpus_audit.py` | `tests.manual.audit_cad_corpus_run` |
| `tests/test_cad_product_acceptance_runner.py` | `tests.manual.run_cad_product_acceptance` |
| `tests/test_p12_eval_budget.py` | `tests.manual.eval_budget_store` |
| `tests/test_recorded_cad_repair_inputs.py` | `tests.manual.run_recorded_cad_repair` |
| `tests/test_user_cad_corpus_runner.py` | `tests.manual.run_user_cad_corpus` |
| `tests/test_cad_history_replay.py` | `tests/manual/replay_cad_history.py` |
| `tests/test_deepseek_flash_budget.py` | `tests/manual/deepseek_flash_budget.py` |

**判断**

这是仓库资产缺失，不是测试断言失败。不得伪造 `tests/manual` 文件，也不得直接删除受影响测试。需要用户决定：补回原始文件、以独立新测试替代，或在 D1 明确标记跳过。

### F-02 A9 历史计划与原始响应不可用

**证据**

- `backend/evaluations/p1.3e_dual_case_frozen.json` 中 A9 的 `historical_plan` 指向外部路径，当前仓库无该文件。
- A9 原始模型响应不在仓库。
- 现有可复用资产只有冻结 prompt、冻结验收和诊断报告中的段 0/段 5 控制点。

**判断**

A9 不能做“历史原始响应精确回放”。D0 只能做 `reconstructed_fixture`：使用精确的段 0/段 5 控制点，加一条合成直线连接段，重建闭合路径。该夹具能复现自交，但不能冒充历史计划。

### F-03 A9 复合路径自相交

**证据**

- 探针：`backend/evaluations/v1/probes/d0_geometry_probe.py`
- 执行结果：`self_intersecting_composite_path`
- 消息：`复合路径包含 1 处自相交`
- 冲突边：`[11,117]`
- 扩展段：`[0,2]`
- 交点区间约 `(2.005822, 3.496668)` 到 `(1.994178, 3.530884)`，与历史诊断交点约 `(2.0, 3.528868)` 高度接近。
- 自交检测代码：`backend/app/cad_construction.py:1151-1195`，关键判断在 1187-1195。

**判断**

A9 的控制点交叉可以被现有执行器独立复现。检测器工作正常；D0 不修复生产几何逻辑。B1 需要在不关闭 `allow_self_intersection=false`、不增加采样点绕过检查的前提下，给出通用全局自相交修复或拒绝策略。

### F-04 `junction_constraints` 在部件合并中丢失

**证据**

- 纯函数探针：`d0_geometry_probe.py` 的 `junction_repair_probe()`。
- 合并前 step keys 包含 `junction_constraints`；合并后不再包含。
- `junction_constraints_preserved=false`，状态 `reproduced`。
- 合并代码：`backend/app/cad_plan_component_repair.py:36-43`，只显式保留 `step_id`、`output_ref`、`semantic`、`layer_id`。
- 修复协议：`backend/app/agent_service.py:6229-6232`，只要求保留其他部件、布局和断言，没有明确保留连接语义。

**判断**

A9 的连接语义丢失可在 Mock/纯函数层独立复现，不需要真实模型响应。A1 应把 `junction_constraints`、`continuity`、`tangent_tolerance_deg` 等连接语义纳入部件合并的保留字段，并在修复协议中显式声明；D0 不修改生产代码。

### F-05 S1 来源验收未检查

**证据**

- S1 重建几何通过：`c1=true`、`joint_count=2`、`failed_joint_count=0`、`maximum_tangent_delta_deg=0.0`、`self_intersection_count=0`。
- 但 `source_acceptance` 当前状态为 `not_checked`，没有当前 `conversation_id`、来源账本或 H3 证据。
- H3.3 报告已明确完整 `conversation_id` 和目标版本自动继承策略仍有缺口。

**判断**

S1 只能记为“重建夹具几何通过”，不能记为“S1 整体通过”。H3 来源验收必须由 C1 在新环境中用真实来源账本或确定性夹具补齐。

### F-06 S1 路由修复仅有单元证据

**证据**

- 路由修复：`backend/app/cad_construction_interpreter.py:170-177`，`explicit_free_curve_scope` 后显式控制点自由曲线进入 `construction_scope`。
- 回归：`tests/test_cad_construction_interpreter.py:115`、`tests/test_agent_orchestration_contract.py:45`。
- 五个专项模块中 `test_cad_construction_interpreter.py` 74 passed。
- 未调用真实模型，未验证真实模型返回的三段 Bezier 几何。

**判断**

路由修复有单元证据，但没有当前端到端证据。C1 需要用一个确定性模型响应或真实受控调用验证 S1 从路由到候选的完整链路；D0 不调用真实模型。

### F-07 HTTP resume 检查点契约与测试夹具不一致

**证据**

- `tests/test_agent_run_api.py`：6 passed，4 failed。
- 失败用例：
  - `test_resume_from_generated_result_skips_model_and_execution`
  - `test_resume_from_prepared_context_skips_context_rebuild`
  - `test_resume_run_api_replays_original_request_into_same_run`
  - `test_resume_run_api_respects_owner`
- `backend/app/agent_http_service.py:754-768` 要求 checkpoint 中存在 `execution_context`，并对去掉 `sha256` 后的对象重新计算哈希；缺失时返回“检查点缺少原始请求上下文，拒绝恢复”。
- 四个测试构造的是旧式 checkpoint：有的没有 checkpoint，有的只有 `result`，有的只有 `prepared_context`，均没有签名的 `execution_context`。

**判断**

这首先暴露的是测试夹具与当前生产契约不一致，不能直接断言“resume 功能坏了”。但也不能宣称 resume 已通过。C1 必须决定：补签 `execution_context` 的测试夹具，或为旧 checkpoint 提供显式迁移；在此之前 HTTP 多轮恢复能力为 `not_run`。

### F-08 HTTP 创建→候选→保存→迭代→版本继承缺少单链 E2E

**证据**

- `tests/test_candidate_save.py`：1 passed，验证保存候选图元的独立性与幂等。
- `tests/test_cad_construction_commit.py`：10 passed，验证候选来源快照、项目修订和重启后账本、非法解释不创建项目、已确认构造留在原项目。
- `tests/test_agent_run_api.py`：6 passed，覆盖 chat/run 持久化、运行详情、取消和部分所有者校验；4 个 resume 失败。
- 没有单个测试同时完成：创建项目 → chat 生成候选 → 保存图纸 → 开始迭代 → 校验父/子版本继承。

**判断**

候选保存和构造提交有模块级证据，HTTP 恢复和多轮版本继承没有端到端证据。C1 需要新增一条确定性 E2E 测试，使用临时项目存储和 Mock 模型响应，不使用真实 DeepSeek。

### F-09 M1 未冻结

**证据**

- M1 没有正式冻结定义。
- 缺少：正式 case_id、自然语言输入、单位、折角位置、允许曲线连接、独立验收字段、期望路由、冻结责任人。
- `backend/evaluations/P1.4 A9-S1-M1真实DeepSeek评测零费用准入报告20261107.md` 已记录该缺口。

**判断**

M1 只能标记 `unfrozen` / `not_run`，不得自行编造，也不得纳入正式评分。

### F-10 6/55 Benchmark 被误当端到端成功率的风险

**证据**

- 6 例文件：`backend/evaluations/cad_construction_model_benchmark.json`，SHA256 `46a9b00dbba14997fa808b62a55d4c7a61d8d3b9dc05887590fd9b30048cc76d`。
- 55 例文件：`backend/evaluations/cad_construction_model_benchmark_extended.json`，SHA256 `f8255040fc670254dd3be69dcaef009bdb81992a2b25fd8e677655a26eec18ba`。
- 规则路径结果：6 例 `passed=0`、`pass_rate=0.0`、`ready_rate=0.3333`；55 例 `passed=6`、`pass_rate=0.10909`、`ready_rate=0.2727`。
- `run_construction_benchmark()` 设置 `read_only=True`、`project_persistence=False`；不创建项目、不写候选、不读凭据、不重试模型调用。
- Benchmark 直接调用解释器，绕过产品路由、H2/H3/H4 和版本写入。

**判断**

这些数字只能作为“规则解释器在构造 Benchmark 上的表现”，不能写成端到端成功率、HTTP 成功率或 H3/H4 通过率。D0 已在 `mock_replay_results.json` 中逐条标注 `outcome_scope=benchmark_interpretation_only`。

### F-11 真实模型脚本存在费用与凭据边界

**证据**

- `backend/run_extended_deepseek_benchmark.py` 是真实模型路径，依赖 `DEEPSEEK_API_KEY`，会实例化 `RobotAgentService` 并调用 `evaluate_construction_interpretation`。
- `backend/run_extended_rule_benchmark.py` 会实例化 `RobotAgentService(restore_pending_actions=False)`，打印 `configured` 和 `api_keys`，再调用 `_interpret_cad_construction_plan`；本机若已配置 Key，可能走真实模型。
- `backend/run_cad_construction_benchmark.py` 要求已配置 provider，否则返回 2。

**判断**

D0 未运行上述脚本。零费用路径使用 `interpret_construction_request(command, None)` 和直接 `execute_construction_plan`，不读凭据、不访问网络。A1/B1/C1 也应优先用确定性夹具；任何真实模型调用必须单独批准并记录 Model 六维证据。

### F-12 `--basetemp` 父目录缺失导致 setup error

**证据**

- `test_cad_requirement_contract.py` 第一次运行出现 6 passed + 1 setup error。
- 原因：`--basetemp` 的父目录 `.tmp` 不存在。
- 创建 `.tmp` 后重跑为 7 passed。

**判断**

这是测试运行器临时目录问题，不是测试失败，也不应记为 `environment_blocked` 的当前阻断。后续命令应显式创建 `.tmp` 或使用已存在的 basetemp 父目录。

### F-13 A9/S1 的 H2/H3/H4 端到端证据缺失

**证据**

- `mock_replay_results.json` 中 A9、S1 的 `acceptance.h2/h3/h4` 均为 `not_checked`。
- H2/H3/H4 代码存在：`cad_requirement_contract.py`、`cad_requirement_ledger.py`、`cad_source_acceptance.py`、`cad_semantic_acceptance.py`。
- 但当前没有 A9/S1 的完整 conversation/source ledger/candidate/version 链路证据。

**判断**

六维证据不完整时必须保留 `not_checked`，不能用历史报告或几何夹具替代 H2/H3/H4。D1 统一回归前，C1 需要补齐端到端证据链。
