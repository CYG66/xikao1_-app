# D1 统一失败分类口径与可复跑入口

适用范围：D 线 D1 及后续每轮对冻结基线与各并行线提交的独立评测。本口径只做诊断与对照，不构成任何生产分支的合并条件。

## 1. 顶层分类（五类，必填）

| failure_class | 含义 | 典型来源 | D0 failure_category 对照 |
|---|---|---|---|
| `collection_blocked` | 收集阶段被阻塞，用例根本没有进入执行；模块导入/资源在 collection 阶段失败 | pytest collection error、缺失冻结仓内 `tests/manual` 资产、模块导入失败 | `collection_blocked` / 缺失冻结仓内用例 |
| `environment_blocked` | 依赖缺失、导入错误、网络/超时、运行期环境缺失导致无法执行，且不是产品断言失败 | ModuleNotFoundError（运行期）、ImportError、ConnectionError/TimeoutError/httpx 超时、缺失本地运行资产 | `environment_blocked` |
| `not_run` | 被跳过、xfail 未触发、未解冻用例、需要真实模型但本轮禁止联网而未触发 | pytest `skipped`、未冻结案例定义、真实模型门控用例 | `not_run` |
| `logic_failure` | 逻辑/断言失败：期望值、几何、图元、约束、验收口径不符 | `AssertionError`、`assert` 比较失败 | `self_intersection` / `topology_invalid` / `geometry_acceptance_mismatch` / `clarification_required` / `benchmark_expectation_mismatch` 等断言类根因 |
| `error_mapping_failure` | 错误映射失败：异常类型不符、错误码/语义不符、未预期异常吞掉了明确错误 | `pytest.raises` 未抛出/抛错类型不符、`ComponentRepairError` 被通用异常吞掉、未预期异常类型 | `error_mismatch` / 约束继承丢失类根因 |

`passed` 为正常通过，不属于失败分类；计数表中单列。

## 2. 判定规则（按优先级）

1. **收集优先**：模块在 collection 阶段报错 → `collection_blocked`，不再归入 `environment_blocked`。收集阶段的 `ModuleNotFoundError`/`FileNotFoundError` 若指向 `tests/manual`，子标签记 `missing_manual_asset`。
2. **测试件级错误**：JUnit `<error>`（setup/teardown/运行期错误）按异常名细分：
   - 网络/超时类（`ConnectionError`、`TimeoutError`、`httpx.ConnectError/ConnectTimeout/ReadTimeout`、`URLError`、`ProxyError`）→ `environment_blocked/network_or_timeout`；
   - `ModuleNotFoundError`/`ImportError`/`SyntaxError` → `environment_blocked/import_or_dependency`；
   - `FileNotFoundError`（运行期缺本地资产）→ `environment_blocked/missing_local_asset`；
   - 其余 setup/运行期环境问题 → `environment_blocked/setup_or_runtime_env`。
3. **跳过**：JUnit `<skipped>` → `not_run/skipped`；未解冻或真实模型门控而未执行 → `not_run/untriggered`。
4. **断言失败**：JUnit `<failure>` 中出现 `AssertionError` 或 `assert` 比较 → `logic_failure/assertion_failure`。
5. **错误映射失败**：
   - `DID NOT RAISE`、`DID NOT MATCH`、`raised ... instead of ...` → `error_mapping_failure/expected_exception_mismatch`；
   - 非 `AssertionError` 的未预期异常 → `error_mapping_failure/unexpected_exception`；
   - 明确业务错误（如 `ComponentRepairError`、`ConstructionPlanError`）被通用 `except Exception` 吞成 `invalid_model_output` → `error_mapping_failure/semantic_swallowed`。

子标签（`sub_class`）用于根因下钻，不改变顶层归类。

## 3. 证据模式红线（防止 Mock 通过率冒充真实模型通过率）

- 每条记录必须标注 `evidence_mode`：`replay_mock` / `reconstructed_fixture` / `rule_parser_zero_cost` / `service_mock` / `live_model`。
- 本轮及后续未获授权前，`live_model` 一律禁止；需要真实模型的用例记 `not_run`，说明原因，不得伪造通过。
- `provider_attempted` 在结果级为 `false` 时，不得解读为真实模型尝试；Harness 校验位中的 `provider_attempted=True` 占位不构成联网证据。
- 服务级 Mock 只证明生产服务回调包装、合并、解释与校验链路在受控输入下的行为；**新增测试通过数量不能直接换算为 CAD 生成通过率**。

### 4.2 任意目标工作树只读回归（同一分类引擎）

```text
python evaluations/v1/probes/d1_baseline_runner.py ^
  --backend "<目标 backend 根目录>" ^
  --label "<目标标签>" ^
  --target-ref "<目标 commit SHA>" ^
  --no-diagnosis ^
  --out "<D 线自有快照 JSON 路径>"
```

- `--no-diagnosis`：目标为其他工作树时跳过 D0 案例诊断（避免读取目标树 D0 资产）。
- 子命令过滤：`--suite S2-plan-component-repair` 只跑单个专项；`--no-collect` 跳过全量收集审计。

## 5. 计数口径

每个专项记录：`tests`（收集用例数）、`passed`、`failed`（断言失败）、`errors`（件级错误）、`skipped`（not_run）、`collection_blocked`、`environment_blocked`、`logic_failure`、`error_mapping_failure`，以及 `pytest_time_s`（pytest 自报）与 `wall_elapsed_ms`（子进程墙钟）。`passed = tests - failed - errors - skipped`。
