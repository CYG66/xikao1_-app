```python
def test_agent_management_routes_are_registered_once() -> None:
    from app.routers.agent import router

    expected = {(method, route.path) for route in router.routes
                for method in getattr(route, "methods", set())}
```

### 已落改的测试断言（选方案 a：注册表双向一致性推导）

选方案 (a) 而非显式 30 条清单：合法新增 agent 路由时，路由器定义与 `app` 注册表会同步增长，推导式检查不误红；显式清单会在每次合法加路由时再次腐化。改后断言结构：

- `expected`：从 `agent.router.routes` 动态构建方法-路径集合；
- `mounted`：从生产 `app.routes` 归集端点模块为 `app.routers.agent` 的方法-路径集合；
- `expected == mounted` 且数量相等：双向一致性，路由器定义与挂载表互不缺漏；
- 逐条 `len(matches) == 1`：恰好注册一次；
- `endpoint.__module__ == "app.routers.agent"`：归属正确；
- `callable(endpoint)`：端点可调用。
- 测试注释指向本调查报告与引入提交 `9302a49`，说明数量不再硬编码的原因。

#### 改后断言能抓住 / 抓不到的缺陷

| 缺陷类型 | 能否抓到 | 依据断言 |
|---|---|---|
| 路由器声明了路由但未挂载到 `app`（缺漏） | 能 | `expected == mounted` 缺键；逐条 `matches` 为 0，`len(matches)==1` 失败 |
| `app` 挂载了 agent 端点但未在路由器定义中登记（多余） | 能 | `mounted` 多出键，集合相等失败 |
| 同一方法-路径重复注册两次 | 能 | 逐条 `len(matches) == 1` 失败（集合去重不会掩盖重复） |
| 路由错挂到其他 owner 模块（或他路端点挂到 agent 路径） | 能 | 归属模块断言失败；且错挂端点不计入 `mounted`，集合相等失败 |
| 端点对象不可调用 | 能 | 新增 `callable(matches[0].endpoint)` 断言 |
| 合法新增一条已正确挂载的 agent 路由 | 不误伤 | 两侧集合同步增长，双向相等成立 |
| Handler 业务逻辑错误、HTTP 状态/响应体错误、鉴权问题 | **抓不到** | 本测试只校验路由表注册与归属，不进入 handler |
| 不同路径模板之间的路由优先级/前缀遮蔽 | **抓不到** | 仅按精确方法-路径比对，不评估 Starlette 匹配顺序 |
| 端点模块名是 agent 但实现委托给其他 owner 的行为归属 | **抓不到** | 只校验 `__module__`，不校验行为归属 |
| 路由器定义内故意写错 HTTP 方法且两侧一致 | **抓不到** | 两侧同步错误时集合相等仍成立，属业务/定义层问题 |

该改动只调整测试护栏口径，不触碰路由实现、请求/响应 Schema 或业务逻辑，不影响既有业务行为。
